# Cognitive Load Theory — 인지 부하 관리 가이드

## 원리

John Sweller (1988~) — 작업 기억(working memory)은 한 번에 *3~7개 청크*만 처리 가능 (Miller 1956). 이 제한 안에서 학습이 일어나야.

> 핵심: 학습 자료가 작업 기억을 *초과*하면 학습 실패. 부하를 *3종*으로 분해해서 관리.

인용 50K+. 가장 잘 검증된 교육학 이론.

## 3종 인지 부하

### 1. 본질 부하 (Intrinsic Load)

**정의**: 학습 자료 *자체의 복잡도*. 학습자가 처리해야 할 *상호연관된 요소 수*.

**관리 방법**: 줄일 수 없음. 학습자 수준에 맞춰 *분할*만 가능.

- 입문 학습자: 한 번에 1~2 요소
- 중급: 3~4 요소
- 심화: 5+ 요소

### 2. 외재적 부하 (Extraneous Load)

**정의**: 학습 자료의 *형식*에서 오는 부하. 학습과 직접 무관.

**관리 방법**: 적극적으로 *줄여야* 함. 학습 효율 직격.

**외재적 부하 원인 (Mayer 12 원칙 위반)**:
- 산만한 비유 / 부적절한 농담
- 텍스트와 그림이 *멀리* 배치 (Spatial Contiguity 위반)
- 같은 정보 여러 채널로 동시 (Redundancy)
- 길고 어려운 문장
- 불필요한 정보 (Coherence 위반)
- 흐름 깨는 형식

### 3. 본질 학습 부하 (Germane Load)

**정의**: 학습자가 *스키마 형성*에 쓰는 부하. *늘려야* 함.

**관리 방법**:
- Worked Examples로 유도
- 회상 점검으로 강화
- 적용 시나리오로 통합

## 본질 부하 관리 패턴

### 분할 (Segmenting)

복잡 주제를 작은 단위로 쪼개기. 각 단위가 *독립적*으로 이해 가능.

```markdown
✅ 좋은 예시 — 분할

### 1. 환경 변수란 (개념만)
한 줄: "프로세스가 들고 다니는 키-값 사전"
시연 1개: `echo $SHELL`
이 섹션은 *환경 변수가 뭔지*만.

### 2. PATH의 정체 (PATH만 따로)
PATH가 환경 변수의 *특별한 케이스*임을 분리.
시연 1개: `echo $PATH`

### 3. PATH 검색 알고리즘 (동작만)
순서대로 뒤지는 방식.
시연 1개: `which python3`
```

```markdown
❌ 나쁜 예시 — 합침

### 환경 변수와 PATH와 자식 프로세스 상속
환경 변수가 뭐고 / PATH가 뭐고 / 자식이 어떻게 상속받고 ...
(작업 기억 3+ 요소 동시 → 처리 불가)
```

### 사전 학습 활성화 (Pre-training)

새 강의 진입 전 *이미 알고 있는 것*을 활성화:

```markdown
> **환기**: 이전 강의에서 *프로세스*를 다뤘다. 프로세스는 자기만의 메모리 공간을 가진다. 이 강의에서는 그 메모리 공간 안의 *환경 변수*를 본다.
```

## 외재적 부하 차단 체크리스트

| 패턴 | 외재적 부하 | 차단 방법 |
|---|---|---|
| 산만한 비유 | 비유가 강의 본질과 멀어짐 | 비유는 1~2개, 강의 본질에 정확히 매핑되는 것만 |
| 부적절한 농담 / 장식 | 학습에 무관 | 제거 |
| 분리 배치 (텍스트 ↔ 그림) | 매핑 부하 | 그림 *직후* 텍스트, 또는 그림에 주석 직접 박기 |
| 중복 정보 (텍스트 + 음성 + 그림 다 같은 것) | 처리 중복 | 한 채널 / 보완적 정보만 |
| 긴 문장 | 파싱 부하 | 한 문장 15~25 음절 |
| 불필요한 디테일 | 핵심에서 멀어짐 | "이 강의에서 다루는 것 / 다음 강의로 미루는 것" 명시 |

## 한 섹션당 새 개념 수 (절대 한도)

| 강의 분류 | 한 섹션당 *새* 개념 최대 |
|---|---|
| 입문 (트랙 첫 시리즈) | **2개** |
| 중급 (트랙 2~4 시리즈) | **3개** |
| 심화 (트랙 후반 시리즈) | **4개** |
| 종합 (시리즈 마지막 강의) | 5개 가능 (앞서 다룬 것 통합이라 본질 부하 낮음) |

## 검증 grep 패턴

```bash
# 평균 섹션 길이 (너무 길면 부하 의심)
SECTION_LINES=$(awk '/^### /{n++; lines[n]=0} /^---$/{exit} {lines[n]++} END{for(i=1;i<=n;i++) sum+=lines[i]; print sum/n}' "$FILE")

# 산만한 농담/장식 (감점)
DISTRACTING=$(grep -cE 'ㅋㅋ|ㄷㄷ|ㅎㅎ|😂|😅' "$FILE")

# 긴 문장 (50음절 초과 라인 수)
LONG_LINES=$(awk 'length > 100' "$FILE" | wc -l)

# 환기 마커 (사전 학습 활성화)
PRE_TRAINING=$(grep -cE '환기:|복습:|이전 강의에서|앞에서 다룬' "$FILE")

# 자기 설명 마커
SELF_EXPLAIN=$(grep -cE '자기 설명|자기 말로|스스로 설명' "$FILE")
```

## 검증 기준

- ✅ 평균 섹션 길이 적정 (입문 ~20줄, 심화 ~40줄)
- ✅ 환기 마커 1+ (사전 학습 활성화)
- ✅ 자기 설명 마커 1+ (germane load 유도)
- ❌ 산만한 농담/장식
- ❌ 한 섹션 새 개념 4+ (입문 강의에서)
