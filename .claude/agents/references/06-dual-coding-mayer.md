# Dual Coding + Mayer's 12 원칙 가이드

## 원리

**Dual Coding** (Paivio, 1971): 텍스트와 시각 정보가 *각각 다른 채널*로 처리되어 *함께 쓰면 학습 효과 2~3배*.

**Mayer's Multimedia Learning** (Mayer 2009): 텍스트+시각 결합의 *12개 검증된 설계 원칙*. 인용 30K+.

> 핵심: 텍스트만 X. 시각 보조 결합. 그러나 *아무 시각이나*는 X — 12개 원칙 위반은 외재적 부하만 추가.

## Mayer's 12 원칙

### 부하 관리 원칙 (Coherence / Signaling / Redundancy / Spatial Contiguity / Temporal Contiguity)

#### 1. Coherence (응집)
**원칙**: 학습과 *무관한* 텍스트/그림/음 *제거*.

**적용**:
- ✅ 본질과 직결되는 다이어그램만
- ❌ 장식용 이모지, 무관한 만화 캐릭터
- ❌ "재미용" 비유 (학습 본질과 안 맞는)

#### 2. Signaling (강조)
**원칙**: *핵심* 정보 시각적 강조.

**적용**:
- ✅ 핵심 결론에 **굵게** / 박스 / 색 강조 (마크다운에서 표 / quote)
- ✅ 다이어그램에서 핵심 박스만 굵은 테두리
- ❌ 모든 줄 굵게 = 강조 효과 0

#### 3. Redundancy (중복 회피)
**원칙**: 같은 정보를 *여러 채널*로 동시 X (학습자가 *비교 처리*하느라 부하).

**적용**:
- ✅ 다이어그램 + 텍스트는 *보완 관계*
- ❌ 다이어그램 옆에 같은 내용 텍스트로 다시 설명 (둘 중 하나만)

#### 4. Spatial Contiguity (공간 인접)
**원칙**: 관련 텍스트와 그림 *물리적 가까이* 배치.

**적용**:
- ✅ 다이어그램 직후에 설명 텍스트
- ✅ 코드 블록 안에 주석으로 설명 박기
- ❌ 그림은 위, 설명은 아래 멀리

#### 5. Temporal Contiguity (시간 인접)
**원칙**: 동시 학습할 정보 *동시* 제시.

**우리 적용 (텍스트 매체)**: 한 섹션 안에 처리.

### 깊은 처리 원칙 (Segmenting / Pre-training / Modality)

#### 6. Segmenting (분할)
**원칙**: 긴 자료를 *학습자 페이스*로 끊을 수 있는 단위로 분할.

**적용**:
- ✅ 각 섹션이 독립 단위 (한 개념씩)
- ✅ 섹션 끝에 회상 점검 마커
- ❌ 한 섹션 500줄

#### 7. Pre-training (사전 학습)
**원칙**: 핵심 개념의 *이름*과 *특징*을 미리 가르침.

**적용**:
- ✅ 첫 섹션에서 용어 4요소 같은 *명명* 후 본격 들어감
- ✅ "이 강의에서 다룰 핵심 용어 3개: A / B / C"

#### 8. Modality (방식)
**원칙**: 그림은 *시각*으로, 설명은 *말/텍스트*로 (둘 다 시각이면 부하).

**우리 적용 (텍스트 매체)**: 다이어그램 안에 텍스트 *최소화*, 본문에서 설명.

### 표상 원칙 (Multimedia / Personalization / Voice / Image)

#### 9. Multimedia (다매체)
**원칙**: 텍스트 *만*보다 텍스트+그림 학습 효과 높음.

**적용 — 우리 시각 자료 종류**:
- ASCII 다이어그램
- 마크다운 표 (매트릭스성일 때)
- Mermaid 다이어그램 (블로그에선 풍부)
- 코드 박스 (자체로 시각)

#### 10. Personalization (인격화)
**원칙**: 대화체 / "너/우리" 어조가 학습 효과 높음.

**적용**:
- ✅ "이 명령을 한 번 쳐보자" / "결과를 보자"
- ❌ "본 강의에서는 다음을 학습한다" (수동적 학술 어조)

#### 11. Voice (음성)
**우리 적용 X**: 텍스트 매체.

#### 12. Image (이미지)
**원칙**: 강사 얼굴 그림은 학습에 *도움 안 됨*.

**우리 적용**: 강의 본문엔 강사 캐릭터 X.

## 시각 자료 종류별 가이드 (텍스트 매체)

### 1. ASCII 다이어그램

**언제 쓰나**:
- 구조/관계 시각화
- 흐름/순서
- 컨테이너 / 계층

**예시**:

```
[프롬프트 4요소]

  ec2-user@ip-172-31-x-x:~$
  └─사용자┘└──호스트──┘└경로┘└권한 기호
```

### 2. 마크다운 표

**언제 쓰나**:
- 옵션 비교 (X × Y 매트릭스)
- 트레이드오프 명시 (장단점)
- 패턴 분류

**언제 쓰지 말까**:
- 흐름/순서 (다이어그램이 나음)
- 단일 차원 정보 (글머리표가 나음)

### 3. 코드 블록 (시각 자료의 한 형태)

```bash
# 한국어 주석은 시각 자료의 일부
ssh -i ~/.ssh/key.pem ec2-user@host
#  └─ 키 파일       └─ 사용자 @ 호스트
```

화살표/주석으로 *시각화* 강화.

### 4. 화살표 / 박스 / 트리

```
A → B → C  (선형 흐름)

  Parent
  ├── Child 1
  └── Child 2  (트리)

  ┌─────┐
  │ Box │  (강조 박스)
  └─────┘
```

## 12 원칙 위반 체크리스트

| 원칙 | 위반 패턴 | 차단 방법 |
|---|---|---|
| Coherence | 장식 이모지/만화 | 강의 본질 무관한 시각 제거 |
| Signaling | 모든 줄 굵게 | 핵심만 강조 |
| Redundancy | 그림 옆 같은 텍스트 | 보완 관계로 |
| Spatial Contiguity | 그림 위 설명 아래 | 그림 직후 설명 |
| Segmenting | 한 섹션 500줄 | 섹션 분할 |
| Pre-training | 용어 없이 본론 | 첫 섹션에 용어 명명 |
| Personalization | 수동적 학술 어조 | "우리/너" 대화체 |

## 시각 자료 갯수

| 강의 길이 | 권장 시각 자료 수 |
|---|---|
| ~300줄 | 3~5개 (표 / 다이어그램 합산) |
| 300~500줄 | 5~8개 |
| 500+ | 8+개 |

## 검증 grep 패턴

```bash
# 시각 자료 카운트
TABLES=$(grep -c '^|' "$FILE")
ASCII_DIAGRAMS=$(grep -cE '→|↓|┌|└|├|│|━' "$FILE")
CODE_BLOCKS=$(($(grep -c '^```' "$FILE") / 2))

# Personalization (대화체)
PERSONAL_TONE=$(grep -ciE '해보자|보자|찍어|쳐보자|우리|너' "$FILE")
FORMAL_TONE=$(grep -cE '본 강의|학습한다|살펴본다' "$FILE")  # 감점

# Signaling (강조)
BOLD_LINES=$(grep -cE '\*\*[^*]+\*\*' "$FILE")
QUOTE_BLOCKS=$(grep -c '^>' "$FILE")

# Pre-training (용어 명명)
TERMINOLOGY_HEADER=$(grep -cE '용어|3요소|4요소|핵심.*개' "$FILE")

# Spatial Contiguity 위반 검사 (수동, grep 한계)
```

## 검증 기준

- ✅ 시각 자료 (표+다이어그램+코드 블록) 합산 ≥ 권장 수
- ✅ ASCII 다이어그램 1+ (단순 표만 X)
- ✅ Personalization 어조 (대화체) > Formal 어조
- ✅ 핵심 강조 (Signaling) 1+
- ✅ 용어 명명 섹션 (Pre-training)
- ❌ 장식 이모지 / 만화 캐릭터
