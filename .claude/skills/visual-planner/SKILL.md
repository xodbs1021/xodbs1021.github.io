# visual-planner

[공통 기준의 시각화·미디어 정책](../blog-writer/references/editorial-policy.md)과 [실제 화면 검수 기준](../blog-writer/references/visual-layout-checks.md)을 먼저 읽는다. 설계한 시각화는 실제 화면의 글자·간격·긴 상태·모바일·다크 모드 검수를 통과해야 한다.

공개 글은 움직이는 설명(영상 또는 단계형 SVG) 1개 이상과 정적 이미지 1개 이상을 갖춘다. 면제는 공통 기준의 승인 절차를 따른다. 수량을 채우려고 그림을 만들지 않는다. 아래 판단으로 설명마다 형식을 정하고, 그 결과로 수량이 채워지지 않으면 어느 설명을 움직임이나 그림으로 보여 줄지 다시 찾는다.

## 1. 후보 찾기

기존 글과 근거를 읽는다(강의 원문은 사용자의 기존 방식대로 `cat`으로 읽는다). 아래 **놓침 신호**가 있는 곳은 모두 후보로 올린다.

- 한 문단이나 이어진 문단에서 같은 단위의 수치 3개 이상을 비교한다.
- 3단계 이상의 순서를 "→", "그다음", "이어서" 같은 글로만 설명한다.
- 서로 연결된 구성 요소 3개 이상의 관계를 글로만 설명한다.
- 상태 이름이 3개 이상이고 전이 조건이 있다.
- 두 주체가 요청·응답을 2번 이상 주고받는다.
- 시간이 흐르며 위치·범위·양이 바뀐다(창이 밀림, 버퍼가 차고 빔, 한쪽이 늦게 따라옴).
- 실제로 일어난 일을 주장한다(오류, 지표 변화, 화면 결과).

## 2. 형식 고르기

후보마다 독자가 봐야 하는 것을 한 줄로 쓰고 형식을 하나 고른다.

| 독자가 봐야 하는 것 | 형식 | 만드는 곳 |
|---|---|---|
| 시간에 따라 바뀌는 모양·순서·속도 | 영상(4–12초 반복, 주장 하나) | [motion-explainer](../motion-explainer/SKILL.md) |
| 정해진 단계 순서를 독자가 넘겨 봐야 함(핸드셰이크, 이벤트 루프, 요청 처리 단계) | 단계형 SVG(이전/다음) | 렌더러가 지원하면 그 컴포넌트, 아니면 영상 |
| 수치 비교·추세·분포 | 그래프 | [echarts-curator](../echarts-curator/SKILL.md) |
| 구성 요소 사이의 관계·경계 | 구성도(Mermaid flowchart, 큰 인터랙티브 구성은 archify) | 이 스킬 |
| 누가 누구에게 무엇을 보내나 | 시퀀스도(Mermaid sequenceDiagram) | 이 스킬 |
| 상태와 전이 조건 | 상태도(Mermaid stateDiagram) | 이 스킬 |
| 여러 항목의 속성·정확한 값 조회 | 표 | 본문 |
| 실제로 일어난 증거 | 스크린샷·로그·대시보드 캡처 | 원자료 |
| 입력을 바꾸면 결과가 어떻게 되나 | 설명 모형(ExplanationLab) | 기존 모형 구현 확인 |
| 물리적·시각적 차이(화질, 픽셀) | 검증 가능한 실제 비교 이미지 | 원자료 |
| 비유가 바로 읽히는 개념 | 생성 이미지(글자 없음, 캡션에 생성 표시) | [gpt-image](../gpt-image/SKILL.md) |

정적 구조(구성도로 충분한 것)를 영상으로 돌리지 않는다. 끝 프레임 한 장으로 같은 정보가 전달되면 영상이 아니라 그림이다. 순서만 보이면 되면 시퀀스도, 독자가 단계를 멈춰 봐야 하면 단계형, 변화의 모양 자체가 정보면 영상이다.

## 3. 과잉 걸러내기

다음은 넣지 않는다.

- 노드 3개 이하의 직선 흐름(문장이 더 짧다).
- 값 2개뿐인 비교.
- 본문 문장을 그대로 다시 그린 그림.
- 같은 내용을 그래프와 표로 중복.
- 의미 없는 색 구분(범주 5개 초과, 범례 없는 색).
- 출처가 불분명한 생성 그림, 실제 화면·측정처럼 보이는 생성 그림.

후보마다 **"이 그림이 없으면 독자가 놓치는 것"**을 한 줄로 적는다. 적을 수 없으면 넣지 않는다.

## 4. 양식

- 색은 강조 하나 + 회색이 기본이다. 지금 독자가 봐야 할 경로·항목 하나만 강조색으로 칠하고, 실패·차단에만 위험색을 쓴다. 강조에는 색 외에 두 번째 단서(굵은 값 라벨, 주석, 점선)를 함께 둔다.
- 글자는 휴대폰 화면에서 실제 12px 이상으로 읽혀야 한다. 넓은 가로 도식은 휴대폰에서 읽히는 형태(세로 배치, 단순화한 핵심 경로)를 함께 준비한다.
- 그림 바로 앞에 무엇을 볼지 한 문장, 바로 뒤에 해석 한 문장을 둔다. 캡션은 "그림 N."과 그림 성격(실측, 문헌값, 설명용 가정, 개념도, 재구성, 스크린샷), 출처를 담는다. 지원 표기법은 현재 `src/lib/posts.mjs`에서 확인하고, 지원하지 않는 속성을 있다고 가정하지 않는다.
- 접근성: 도식에는 제목과 짧은 설명(Mermaid `accTitle`/`accDescr`), 그래프에는 핵심 결론을 본문 텍스트로도 제공한다.

## 결과

후보별로 표를 만든다: 위치 / 놓침 신호 / 독자가 봐야 하는 것 / 형식 / 없으면 놓치는 것 / 근거 종류 / 필요한 원자료. 걸러낸 후보와 이유도 함께 적는다. 공개 글 필수 수량(움직이는 설명 1, 정적 이미지 1)을 충족하는지 마지막 줄에 적는다.

필요한 경우만 코드·config 초안을 붙인다. 이미지 프롬프트는 [image-prompt-curator](../image-prompt-curator/SKILL.md), 이미지 생성은 [gpt-image](../gpt-image/SKILL.md), 그래프는 [echarts-curator](../echarts-curator/SKILL.md), 영상·정지 프레임은 [motion-explainer](../motion-explainer/SKILL.md)로 연결한다. `.claude/agents/image-need-judge.md`, `.claude/agents/echarts-advisor.md`의 관점은 독립 위임을 실제로 했을 때만 협업 결과라고 보고한다.

계획만 요청받았으면 계획을 보고하고, 글 작성·수정까지 요청받았으면 그 범위에서 바로 적용한다.
