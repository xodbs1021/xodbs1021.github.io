# visual-planner

[공통 기준의 시각화·미디어 정책](../blog-writer/references/editorial-policy.md)을 먼저 읽는다.

[실제 화면 검수 기준](../blog-writer/references/visual-layout-checks.md)을 함께 적용한다. 설계한 시각화는 실제 화면의 글자·간격·긴 상태·모바일 검수를 통과해야 한다.

1. 기존 글과 근거를 읽는다. 강의 원문은 사용자의 기존 방식대로 `cat`으로 읽는다.
2. 독자가 이해해야 할 관계·차이·순서를 후보로 만든다. 후보 개수도 이미지 개수도 미리 정하지 않는다.
3. 필요하면 `.claude/agents/image-need-judge.md`, `.claude/agents/echarts-advisor.md`의 관점을 적용한다. 독립 위임을 실제로 했을 때만 협업 결과라고 보고한다.
4. 아래 기준으로 한 후보의 주된 표현을 고른다. 같은 내용을 이미지와 차트로 중복 생성하지 않는다.

| 설명하려는 것 | 우선 검토할 표현 |
|---|---|
| 수치 비교·추세·분포 | ECharts; 조건·단위·출처 확인 |
| 정확한 값 조회·서로 다른 단위의 스펙 | 표 또는 차트와 작은 데이터 표 |
| 요청 흐름·상태 전이·결정 과정 | Mermaid 또는 적합한 다이어그램 |
| 픽셀·화질·공간 구조 차이 | 실제 비교 이미지 또는 정확한 도식 |
| 비유로 이해하기 쉬운 개념 | 이미지; 단순 장식인지 점검 |
| 입력 변화에 따른 지연·복구·인증 결과 | 인터랙션; 모형 여부·정적 대체 설명 표시 |
| 이미 충분히 설명한 내용 | 기존 글/이미지 링크 |
| 한두 문장으로 명확한 사실 | 텍스트 |

## 결과

후보별 위치, 독자가 얻는 정보, 근거 종류, 선택한 표현, 필요한 원자료를 표로 정리한다. 필요한 경우만 코드/config 초안을 붙인다. 이미지 프롬프트는 `../image-prompt-curator/SKILL.md`로, 차트 검토는 `../echarts-curator/SKILL.md`로 연결한다.

이미지 0개도 여러 개도 가능하다. 과거 글의 개수를 비교해 이번 수량을 보정하지 않는다. 계획만 요청받았으면 계획을 보고하고, 글 작성·수정까지 요청받았으면 그 범위에서 바로 적용한다.
