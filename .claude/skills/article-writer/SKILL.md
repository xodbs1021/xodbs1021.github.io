# article-writer

먼저 [공통 기준](../blog-writer/references/editorial-policy.md), [글쓰기 원칙](../blog-writer/references/writing-principles.md), [글 유형](../blog-writer/references/post-types.md)을 읽는다. 사이트 계약·초안/발행 구분·시각 자료 필수 규칙은 공통 기준을 따른다. 이 스킬은 독자가 판단을 따라가고 결과의 범위를 이해할 수 있는 심층 아티클의 작성 순서를 정한다.

## 입력과 근거

주제, 대상 독자, 제공된 코드·실험·문헌, 작성/발행 범위, 사용자·팀원·AI의 역할을 파악한다. "수치가 있다"는 말과 실제 제공된 수치는 다르다. 없는 파일이나 실측값은 만들어 채우지 않는다. 원자료가 필요하면 해당 자료만 질문하면서 개념·구조 초안을 진행한다.

`_workspace/blog/<slug>/evidence.md` 머리에 고른 [글 유형](../blog-writer/references/post-types.md)을 적고, 주요 주장과 근거(원본 경로·URL·커밋·확인 날짜·측정 조건·수행 주체·확인 범위)를 정리한다. 문헌 해설에 개인 구현 경험을 덧붙이지 않는다.

## 작성

1. **뼈대.** 유형의 순서를 출발점으로 소제목만 먼저 쓴다. 소제목을 이어 읽어 줄거리가 되는지 확인한다. 주제에 필요 없는 절은 뺀다. 모든 글에 셋업·코드·벤치마크를 강제하지 않는다.
2. **본문.** `_workspace/blog/<slug>/draft.md`에 `draft: true`로 쓴다. 첫 문단은 문제와 원인·결과로 시작하고, 글쓰기 원칙을 지키며, 원문과 문장 단위로 대조한다.
3. **코드.** 실행 예제와 설명용 발췌를 구분한다. 실행 예제는 전제·버전(`latest` 금지)·필수 설정·확인 방법을, 발췌는 생략된 맥락을 표시한다. 실행하지 않은 코드를 실행 검증했다고 쓰지 않는다.
4. **수치.** "빠르다", "효율적이다"는 조건이 붙은 수치로 바꾼다. 수치가 없으면 확인한 범위와 정성 비교만 쓴다. 문헌값을 개인 실험 결과로 바꾸지 않는다.
5. **시각 자료.** `../visual-planner/SKILL.md`로 설명마다 형식을 고르고 만든다. 공개 글의 영상·이미지 필수 규칙과 면제 절차는 공통 기준을 따른다.
6. **출처.** 독자가 바로 받아들이기 어려운 주장마다 공개 링크를 달고 글 끝 `## 출처`에 모은다. 링크 개수를 채우지 않는다.

## 검토와 발행

1. `.claude/agents/blog-quality-reviewer.md`로 사실·수치·역할·링크·화면을 먼저 검토한다.
2. `.claude/agents/article-style-checker.md`로 문장·구조를 검토한다. 사실 오류는 문체 점수로 통과시키지 않는다.
3. 문제를 보완하고 `review.md`에 남은 검증 한계를 기록한다.
4. 초안 요청은 여기서 완료한다. 발행 지시가 확보됐을 때만 `.claude/agents/publisher.md`로 진행한다.

에이전트 파일은 역할 지침이다. 실제로 위임하지 않은 검토를 위임한 것처럼 보고하지 않는다.

결과에는 초안 파일 또는 확인한 공개 URL(`https://taeyun.blog/posts/.../`), 고른 유형, 시각 자료 목록(형식·근거 종류), 검증 범위, 미확인 자료를 적는다. push 성공을 발행 완료로 표현하지 않는다.

## 회귀 평가

행동 평가를 수정할 때 `../article-writer-workspace/evals/evals.json`의 현재 기준을 사용한다. 과거 iteration 결과는 당시 기록이며 현재 정책의 정답이 아니다. 평가 시 외부 발행을 실제로 수행하지 않고 격리된 작업 폴더를 사용한다.
