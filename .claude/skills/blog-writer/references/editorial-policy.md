# 블로그 작성·검수·발행 공통 기준

이 파일은 blog-writer, article-writer와 관련 에이전트가 공유하는 기준이다. 현재 요청과 확인된 사용자 선호를 먼저 적용한다. 스킬 선택 자체는 공개 발행이나 외부 서비스 전송의 허가가 아니다.

## 사실과 저자 역할

- 주요 주장마다 근거를 작업 메모에 연결한다: 주장 / 원본 경로·URL·커밋 / 확인 날짜 / 측정 조건 / 수행 주체 / 확인 범위.
- 근거를 `실측`, `문헌값`, `가정·모형`, `미검증`으로 구분한다. 본문에도 독자가 오해할 수 있는 차이를 밝힌다. 작업 메모 자체를 공개할 필요는 없다.
- 사용자 결정·설계·검증 기준, 팀원 구현, AI 구현·실행을 구분한다. 코드가 저장소에 있거나 PR 작성자로 표시된 것만으로 사용자가 직접 구현·측정했다고 쓰지 않는다.
- 개인 프로젝트·이력은 저장소 AGENTS.md의 canonical source 경로를 따른다. 제출 당시 주장, 이후 정정, 제안, 구현, 검증 결과를 섞지 않는다. 과거 메모는 날짜를 확인한다.
- `직접 구현했다/테스트했다`는 확인된 역할일 때만 사용한다. 문헌 해설은 문헌 해설로, AI가 수행한 실험은 그 수행 주체와 사용자의 판단을 구분해 쓴다.
- 숫자는 주장을 뒷받침할 때 사용한다. 없는 실측값을 추정하거나, 타인의 벤치마크를 사용자 결과로 바꾸거나, 설명용 숫자를 실측으로 표시하지 않는다. 자료가 없으면 정성 설명과 검증 계획으로 초안을 진행하고 필요한 원자료만 질문한다.
- 실측에는 버전·환경·조건·반복 횟수·집계 방식 중 해석에 필요한 정보를 붙인다. 단위(MB/Mb, 초/분), 비율의 분모, 제목·본문·표·차트의 수치 일치를 확인한다. 부분 복구를 전체 데이터 복구로 확대하지 않는다.
- 출처 개수가 아닌 핵심 주장 근거의 충분성을 검토한다. 공식 문서, 논문, 코드·로그·PR 등 원자료를 해당 문장 가까이 연결한다. 버전·요금·표준 등 변동 가능한 내용은 작성 시 공식 자료로 확인한다. 예시는 확인한 버전을 사용하며 `latest`를 재현 가능한 버전처럼 제시하지 않는다.

## 초안과 공개 발행

- `써줘/정리해줘/초안만`은 기본적으로 초안 작성이다. `올려줘/발행해줘/배포해줘` 또는 같은 세션의 유효한 발행 지시가 있으면 검증 후 발행까지 진행한다. 이미 받은 승인을 반복해서 묻지 않는다.
- 새 글 초안은 `draft: true`, 작업 경로는 `_workspace/blog/<slug>/draft.md`. 리뷰와 근거 메모도 그 폴더에 둔다. 다른 초안을 옮기거나 덮어쓰지 않는다.
- 공개 글의 수정 초안은 작업 폴더 사본에서 작성한다. 초안 요청만으로 공개 원문의 draft 상태나 내용을 바꾸지 않는다.
- 발행 범위가 확보되고 사실·링크 검토가 끝나면 발행 대상 사본을 `draft: false`로 전환한다. 초안이 배포에서 제외되는 것은 정상이다.
- 사실 오류, 역할 오인, 미검증 실측 주장, 비밀 노출은 발행 차단 사유다. 근거로 해결하거나 해당 주장을 제거·제한한다. 문체 점수로 상쇄할 수 없다.
- 검토 실패를 검토 통과로 보고하지 않는다. 수정 가능한 문제는 보완하고, 빠진 근거 등 해결 불가능한 항목만 사용자에게 구체적으로 알린다.

## 현재 사이트 계약

- 운영: Astro + Vercel, canonical `https://taeyun.blog/`. `astro.config.mjs`, `package.json`, `src/lib/posts.mjs`, `src/lib/taxonomy.mjs`가 실제 구현의 기준이다. 구현이 바뀌면 이 문서도 맞춘다.
- `content/posts/<folder>/<slug>.md` → `/posts/<folder>/<slug>/`. 기존 폴더·파일명은 URL 계약이므로 카테고리 변경 때문에 이동하지 않는다.
- 새 글의 categories는 `projects`(프로젝트 기록), `open-source`(오픈소스), `technical-notes`(기술 해설), `notes`(개발 노트) 중 주제에 맞는 하나. 기술 이름은 tags, 연속 글은 현재 시리즈 구현을 확인해 연결한다. 새 글은 같은 이름의 폴더를 사용할 수 있다.
- 옛 분류 요청은 taxonomy의 매핑을 사용한다. `coding-test` 등 일대일 매핑이 없는 요청은 내용에 따라 분류하고 선택을 알린다. 단순 분류 선택만으로 작업을 멈추지 않는다.
- 기존 date를 수정 시각으로 덮어쓰지 않는다. 새 글 날짜는 `TZ=Asia/Seoul date '+%Y-%m-%dT%H:%M:%S%:z'`를 지원하는 환경에서 사용하거나, macOS에서는 `TZ=Asia/Seoul date '+%Y-%m-%dT%H:%M:%S%z'`의 실제 출력을 사용한다. 임의 미래 날짜를 만들지 않는다. 현재 로더는 미래 글을 제외한다.
- 새 글 frontmatter: title, date, description, categories, tags, draft. `weight`는 사용하지 않는다. description은 글 고유의 내용을 요약한다.
- 정적 원본은 `static/images/`, 참조는 `/images/...`. 공개 원본과 기존 경로를 보존한다. `dist/`는 빌드 결과이므로 직접 수정하지 않는다.
- 기존 chart shortcode와 Mermaid를 현재 Astro 로더가 지원한다. 새 표기법이나 MDX 지원을 가정하지 말고 실제 렌더러를 확인한다.
- 검색은 빌드된 MiniSearch 색인이다. Hugo/Pagefind 재색인 명령을 사용하지 않는다.
- 옛 GitHub Pages는 이전 주소 리다이렉트용이다. GitHub Actions 성공만으로 Vercel 공개 배포 완료를 선언하지 않는다.

## 시각화와 미디어

- 시각화 수량의 최소값을 정하지 않는다. 후보별로 독자가 이해할 차이·관계·순서를 먼저 정한다. 이전 글의 개수를 따라 하거나 일부러 다른 개수를 만들지 않는다.
- 수치의 비교·추세·분포는 ECharts를 적극 우선한다. 적은 수의 정확한 값 조회나 서로 단위가 다른 스펙 나열은 표가 더 명확할 수 있다. 선택 근거를 짧게 남긴다.
- 차트에 단위·조건·출처를 표시한다. 가정·모형은 캡션과 주변 설명에 표시하고, 모형의 입력·계산 규칙을 제공한다. 빈 데이터를 채우기 위해 임의 벤치마크를 만들지 않는다.
- 흐름·상태는 Mermaid/적절한 다이어그램, 호환성·옵션 매핑은 표, 물리적·시각적 차이는 검증 가능한 이미지로 설명한다. AI 생성 이미지로 실제 HDR/코덱 화질 비교나 실험 스크린샷을 위조하지 않는다.
- 인터랙션은 입력을 바꾸어 원인과 결과를 이해하는 데 유용할 때 사용한다. 초기 상태·리셋·키보드 조작·모바일·정적 대체 설명을 포함한다. 설명용 모형과 실제 제품 동작을 구분한다.
- 원본 이미지 외에 필요하면 반응형 WebP/AVIF 파생본을 만든다. 확장자만 바꾸지 않는다. 적절한 alt, 크기 정보, 캡션·출처를 제공한다. 현재 렌더러가 지원하지 않는 속성은 구현·검증 없이 있다고 가정하지 않는다.
- 영상은 포스터·사용자 재생·불필요한 사전 다운로드 방지를 고려한다. 큰 원본을 무조건 저장소에 추가하거나 유료 미디어 서비스를 자동 연결하지 않는다.
- 외부 이미지 공급자는 현재 환경과 요청에 맞춰 명시적으로 선택한다. 공급자·모델·출처 URL·저작자·이용 조건·생성 여부를 작업 메모에 남긴다. 비공개 자료를 임의의 공급자에 보내거나 실패 시 다른 공급자로 몰래 전환하지 않는다.

## 확인과 완료 보고

- [실제 화면 검수 기준](visual-layout-checks.md)을 필수로 적용한다. 자간·행간·그룹 여백·입력 정렬·모바일/상태별 렌더링을 코드와 화면에서 확인하고 회귀 검사로 남긴다.

- 변경된 글의 제목·본문·수치·역할·링크·이미지와 모바일 레이아웃을 확인한다. 관련 자동 검증은 현재 package.json을 사용한다.
- 초안은 공개 빌드에서 제외되므로 실제 렌더링이 필요하면 격리된 임시 checkout에서 초안 사본만 `draft: false`로 빌드한다. 로컬 preview는 외부에 공개하지 않고, 임시 공개 사본은 커밋·push하지 않는다.
- 발행 절차는 `.claude/agents/publisher.md`를 따른다. 결과에는 초안/검수/커밋/push/배포/실제 URL 확인을 구분한다. Search Console 제출과 실제 Google 색인을 구분하며 노출을 보장하지 않는다.
