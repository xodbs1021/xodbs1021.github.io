# 글 유형별 뼈대

[공통 기준](editorial-policy.md)과 [글쓰기 원칙](writing-principles.md)을 먼저 읽는다. 초안을 쓰기 전에 아래 유형 중 하나를 고르고 `_workspace/blog/<slug>/evidence.md` 머리에 적는다. 뼈대는 토스 기술 블로그 글 20편(2024-10~2026-11)에서 공통으로 보인 순서를 우리 정책에 맞게 옮긴 것이다. 절 이름은 그대로 쓰지 않고 그 절의 결론을 소제목으로 쓴다.

모든 유형에 공통으로 들어가는 것:

- 첫 문단: 상황 → 문제 → 원인이나 결과(수치가 있으면 전후 값).
- 막힌 지점·기각한 대안·남은 한계를 다루는 절.
- 끝: `## 출처`. 실측이 있으면 그 앞에 `## 측정 조건`(버전·환경·반복·집계 방식).
- 시각 자료는 `visual-planner`가 설명마다 형식을 고른다. 아래 「맞는 시각 자료」는 출발점일 뿐 필수 목록이 아니다.

## 트러블슈팅

증상을 재현하고 원인을 좁혀 고친 기록.

1. 맥락과 증상(수치), 결론 먼저
2. 평균 지표나 첫 가설로는 안 보였던 것
3. 원인 추적: 도구와 관찰을 단계별로
4. 근본 원인: "왜 하필 여기서"
5. 조치와 기각한 대안
6. 무엇이 달라졌나: 같은 축의 전후 비교
7. 비슷한 상황이라면(선택): 독자가 일반화할 판단
8. 측정 조건 · 출처

맞는 시각 자료: 증상 재현 반복 영상, 실제 로그·대시보드 캡처, 전후 비교 그래프(같은 축).

## 의사결정

여러 선택지 중 하나를 고른 이유.

1. 결정이 필요해진 증상이나 제약
2. 선택지와 판단 기준
3. 증상·기준 하나당 절 하나: 각 선택지가 어떻게 됐나
4. 선택과 대가: 무엇을 포기했나
5. 남은 위험과 다시 판단할 조건 · 출처

맞는 시각 자료: 선택지 비교 표, 기준별 수치 그래프, 결정 전후 구성도.

## 설계·아키텍처

구성 요소와 경계, 요청 흐름을 정한 기록.

1. 풀어야 했던 공통 문제
2. 첫 시도와 그 한계
3. 구조: 구성 요소와 책임 경계
4. 요청 하나가 지나가는 경로
5. 어려웠던 지점과 기각한 구조
6. 검증 결과와 현재 상태(제안/구현/운영 구분)
7. 다음 방향 · 출처

맞는 시각 자료: 전체 구성도(정적), 요청 경로 하나를 강조한 반복 영상, 메시지 순서는 시퀀스도.

## 이전·개편 회고

오래된 것을 새것으로 바꾼 과정.

1. 규모가 드러나는 배경
2. 고쳐 쓰지 않고 새로 하기로 한 결정과 이유
3. 과도기: 둘이 함께 돈 기간
4. 새 구조
5. 멈춤과 실패
6. 결과와 남은 것
7. 다음 편(시리즈면 링크만) · 출처

맞는 시각 자료: 결정 타임라인, 전후 구성도, 이전 진행률 그래프.

## 따라 하기(How-to)

독자가 같은 결과를 재현하는 절차.

1. 왜 필요한가
2. 대안 비교와 선택
3. 준비물: 확인한 버전
4. 단계별 명령과 출력(복사해 실행할 수 있게, 버전 고정)
5. 확인 방법과 운영 시 주의
6. 출처

맞는 시각 자료: 대안 비교 표, 단계 순서를 넘겨 보는 단계형 SVG, 실제 출력 캡처.

## 실험·벤치마크

조건을 정해 측정하고 해석한 기록.

1. 무엇을 비교하나와 품질 기준
2. 도구와 환경을 고른 이유
3. 병목 측정
4. 개선 전후
5. 일반화: 다른 사람이 쓸 수 있는 기준
6. 한계: 측정하지 않은 것
7. 측정 조건 · 출처

맞는 시각 자료: 조건별 그래프(단위·축 명시), 측정 구성도, 실측 원자료 표.

## 기술 해설

표준·프로토콜·도구의 동작 원리를 설명하는 글.

1. 이 기술이 등장한 이유와 풀려는 문제
2. 핵심 개념 정의(한두 문장씩)
3. 동작 원리: 시간 순서나 데이터 흐름
4. 다른 접근과의 비교와 장단점
5. 실무에서 갈리는 판단과 흔한 오해
6. 출처

맞는 시각 자료: 시간에 따라 바뀌는 메커니즘은 영상, 프로토콜 순서는 단계형 SVG, 패킷·구조는 주석 붙인 도식.
