# 실제 화면 검수: 발행 차단 기준

블로그 글 작성·수정과 공통 CSS/컴포넌트 변경에 적용한다. HTML 생성, 빌드 성공, 링크 검사만으로 화면 검수를 통과시키지 않는다. `blog-writer`, `visual-planner`, `blog-quality-reviewer`, `publisher`가 공유한다.

## 실행과 범위

1. `npm run build && npm test` 후 `npx playwright install chromium`, `npm run test:layout`을 실행한다. CI는 같은 브라우저 검사를 수행한다. `test-results/layout/report.json`과 PNG가 증거다.
2. 기본 검사는 sitemap 및 빌드 결과의 **모든 공개 블로그 경로**를 320·390·768·1440px에서 검사한다. 공통 스타일/렌더러 변경이나 전수점검 요청에서는 범위를 줄이지 않는다. 특정 글의 국소 수정만 `LAYOUT_PATH=<slug> npm run test:layout`로 좁힐 수 있으며 범위를 보고한다.
3. 검사기는 모든 글의 문서 넘침·본문 잘림·단락 행간·자간·제목/본문 정렬을 확인한다. 모든 차트·도식을 390/1440px 및 모바일 다크 모드에서 **그 폭에 실제로 보이는 판(wide/narrow)** 기준으로 캡처하고, 실제 렌더 글자 크기·첫 화면에 보이는 비율·대비·`<title>`/`<desc>`·그림 발 레이아웃 이동을 잰다. 스크롤되는 그림만 `-end.png`(실제 스크롤 끝)를 보조로 남긴다. 정적 그림뿐인 글이 도식·차트 런타임(ELK·ECharts·Mermaid 청크)을 받으면 `report.json`의 `warnings`에 남는다. 모형 3종/4개 글은 초기·변경·긴 결과·키보드 초기화 상태를 4개 폭 및 밝은/어두운 화면에서 검사한다.
4. `report.json`의 실패와 PNG를 **직접 확인**한다. 변경 컴포넌트는 각 폭·테마·긴 상태를 반드시 본다. 공통 시각화 변경은 전체 캡처를 contact sheet로 훑고 작거나 잘린 항목을 원본 크기로 확대한다. 캡처를 만들기만 하고 시각 검수를 완료했다고 쓰지 않는다.
5. 폰트와 동적 렌더러가 준비된 뒤 캡처한다. 외부 폰트가 실패하면 대체 폰트 상태를 별도로 확인하고 원래 폰트 확인을 대신했다고 쓰지 않는다. 검사 범위·스크린샷·실패/수정 결과·미확인 범위를 리뷰에 남긴다.

## 판정 기준

- **글자**: 본문 16px 이상, 행간 1.6~1.9를 기본으로 한다. 글 제목은 1.35~1.5. 한국어는 어절 단위로 줄바꿈하되 긴 URL/식별자는 넘치지 않게 한다. 양쪽 맞춤·임의 공백으로 정렬하지 않는다. 본문/컨트롤 자간은 normal, 글 제목은 -0.025em보다 조밀하게 만들지 않는다. 로고 등 예외를 본문 전체에 확산하지 않는다.
- **간격**: 모형의 독립 그룹 사이 20px, 버튼 묶음→결과 상자 최소 12px, 레이블→입력 8px. 상자 안 여백과 상자 밖 간격은 별개다. 전역 `p` 여백, margin collapse, 선택자 우선순위까지 실제 bounding box로 확인한다. 버튼과 결과 상자가 붙으면 발행 차단이다.
- **입력/버튼**: 체크박스와 문장을 수직 가운데 정렬한다. 셀렉트/체크박스 행/버튼 터치 영역 최소 44px. 줄이 길어지거나 모바일에서 줄바꿈되어도 컨트롤·숫자·단위·결과가 겹치거나 잘리지 않는다. 성공뿐 아니라 거절/누락/최대값/긴 설명/초기화 상태를 본다.
- **본문 폭**: 제목·설명·본문·본문 끝 메타의 왼쪽 선과 폭을 맞춘다. 페이지 가로 스크롤은 차단 사유다. 코드·넓은 표의 **내부 스크롤**은 허용하되 내용이 실제로 끝까지 읽혀야 한다. `overflow:hidden`으로 오류를 숨기지 않는다.
- **그림/차트**: 도식·차트는 빌드 때 만든 정적 SVG다(도식은 `npm run render:diagrams`로 미리 렌더해 커밋, 차트는 빌드가 360·720px 두 벌을 만든다). 아래는 검사기가 실패로 처리한다.
  - 실제 렌더 글자 12px 미만. 그림을 줄여 맞추되 글자가 12px 아래로 내려가면 좁은 판(TB 도식, 가로 막대 차트)으로 바뀌어야 한다.
  - 390px 첫 화면에 그림의 80% 미만이 보임(가로 스크롤). 예외는 메타데이터가 아직 없는 옛 그림(`data-scroll="allowed"`, `warnings`에 기록)뿐이다. `kind`·`caption`을 갖춘 새 그림은 스크롤 없이 맞아야 한다.
  - 글자 대비 4.5:1 미만(노드 글자는 노드 면, 나머지는 그림 면 기준), 차트 데이터 표식 3:1 미만, 캡션 4.5:1 미만.
  - 다크 화면에 하드코딩된 흰색·검은색 면이 남음. 색은 `src/styles/visual-tokens.json` 토큰(CSS 변수)만 쓴다.
  - SVG에 `<title>`이 없음, 차트에 `<desc>`가 없음, 그림에서 생긴 레이아웃 이동, 렌더 결과가 없는 도식(`diagram-missing`).
  축·범례·노드·캡션의 충돌·잘림은 여전히 캡처를 눈으로 확인한다. 캡션은 렌더러가 "그림 N."을 붙인다.
- **상호작용/대체 화면**: 키보드 포커스 표시와 Enter/방향키 조작, reset 결과, JavaScript 비활성 정적 설명을 확인한다. 숨긴 컨트롤이 작동하는 것처럼 보이면 안 된다. 밝은/어두운 화면의 경계선·텍스트 대비와 200% 확대에서도 검수한다.

## 수정과 배포

수정은 원본 CSS/컴포넌트에 한다. `dist` 임시 패치, 검사 임계값 완화, 실패 항목 무시로 통과시키지 않는다. CSS는 컴포넌트별로 모으고 같은 요소에 상충하는 여백을 누적하지 않는다. 발견한 회귀는 동작/기하 검사에 추가하고, 가능하면 이전 CSS에서 실패하는지 확인한다.

검수 통과 후 기존 발행 절차를 따른다. 실제 배포가 완료되면 `LAYOUT_URL=https://taeyun.blog LAYOUT_PATH=<변경 대표 slug> npm run test:layout`로 공개 결과까지 확인한다. 배포된 커밋·실제 응답·레이아웃을 확인하기 전에는 수정 완료라고 보고하지 않는다. 자동 검사는 시각 검토를 보완하며, 모든 미래 문제를 방지한다고 보장하지 않는다.
