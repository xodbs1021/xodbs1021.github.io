# echarts-curator

[공통 기준](../blog-writer/references/editorial-policy.md)과 [visual-planner](../visual-planner/SKILL.md)의 판단을 먼저 읽고, `.claude/agents/echarts-advisor.md`의 차트 검토 기준을 적용한다.

## 원칙

- 같은 단위의 수치 3개 이상을 비교하는 문장·표는 그래프 후보다. 표만 늘어놓지 않는다. 다만 값 2개 비교, 정확한 값 조회, 단위가 서로 다른 스펙, 호환성 매트릭스는 표나 문장이 더 명확하다. 표가 나은 경우도 이유와 함께 보고한다.
- 차트 최소 개수는 없다. 데이터가 없으면 없다고 알리고 근거 확보 또는 명시적인 설명용 모형을 제안한다. 모형의 숫자도 계산 규칙 없이 꾸며 넣지 않는다.
- 실측/문헌값/설명용 가정을 구분하고 출처·단위·조건을 캡션과 주변 본문에 표시한다.
- 같은 척도에서 비교 가능한지, 비율의 분모와 합계가 맞는지, 축 잘림·로그 축이 오해를 만드는지 검토한다. 막대는 0에서 시작한다.

## 양식

- **색**: 강조 계열 하나 + 나머지 회색. 사이트 토큰(accent, data-muted, danger)을 쓰고 Tailwind 같은 임의 hex를 쓰지 않는다. 범주를 색으로 구분해야 하면 최대 4개, 노랑은 쓰지 않는다. 범주가 5개를 넘으면 차트를 다시 설계한다.
- **라벨**: 범례보다 선·막대 옆 직접 라벨. 라벨을 회전하지 않는다. 핵심 지점 하나에 `markLine`이나 `markPoint`로 주석을 단다.
- **축**: 이중 y축을 쓰지 않는다. 두 척도를 비교해야 하면 작은 차트 두 개로 나눈다. 로그 축은 범위 차이가 100배 이상일 때만 쓰고 캡션에 밝힌다.
- **휴대폰**: 360px 폭에서 데이터가 첫 화면에 보여야 한다. 범주형은 가로 막대를 우선하고, 긴 범주 이름은 줄인다. 축 이름이 길면 캡션으로 옮긴다.

## 데이터 형태별 시작점

| 데이터 | 권장 시작점 |
|---|---|
| 범주별 값 | 가로 bar |
| 시간·순서의 변화 | line |
| 부분/전체 비율 | stacked bar(파이·도넛은 3조각 이하일 때만) |
| 두 수치의 관계 | scatter |
| 전후 비교 | 같은 축의 bar 두 계열 또는 slope |
| 매우 큰 범위 차이 | log 축 검토; 0·음수 처리와 축 표기 확인 |

## 렌더러

`src/lib/posts.mjs`와 차트 클라이언트·서버 렌더 코드를 확인해 지원 표기법을 쓴다. 기존 `{{< chart caption="..." >}}` 블록은 유지할 수 있다. 내부는 JavaScript 함수가 아닌 JSON으로 파싱 가능한 ECharts option이어야 한다. 렌더러가 지원하지 않는 속성을 있다고 가정하지 않는다.

추천 요청은 위치·이유·config를 반환한다. 적용 요청은 해당 글만 변경하고 빌드와 PC/모바일 렌더링, 다크/라이트 가독성을 확인한다. 실제 적용 권한이 이미 있으면 재승인을 요구하지 않는다.
