# echarts-curator

[공통 기준](../blog-writer/references/editorial-policy.md)과 [visual-planner](../visual-planner/SKILL.md)의 판단을 먼저 읽고, `.claude/agents/echarts-advisor.md`의 차트 검토 기준을 적용한다.

## 원칙

- 같은 단위의 수치 3개 이상을 비교하는 문장·표는 그래프 후보다. 표만 늘어놓지 않는다. 다만 값 2개 비교, 정확한 값 조회, 단위가 서로 다른 스펙, 호환성 매트릭스는 표나 문장이 더 명확하다. 표가 나은 경우도 이유와 함께 보고한다.
- 차트 최소 개수는 없다. 데이터가 없으면 없다고 알리고 근거 확보 또는 명시적인 설명용 모형을 제안한다. 모형의 숫자도 계산 규칙 없이 꾸며 넣지 않는다.
- 실측/문헌값/설명용 가정을 구분하고 출처·단위·조건을 캡션과 주변 본문에 표시한다.
- 같은 척도에서 비교 가능한지, 비율의 분모와 합계가 맞는지, 축 잘림·로그 축이 오해를 만드는지 검토한다. 막대는 0에서 시작한다.
- 그래프·표는 ECharts · Mermaid · 마크다운 표 같은 렌더 도구로 만든다. 생성 이미지(gpt-image 등)로 그래프·표·수치 그림을 만들지 않는다.

## 양식

- **색**: 강조 계열 하나 + 나머지 회색. 색을 지정할 때는 `src/styles/visual-tokens.json`의 밝은 테마 값만 쓴다 — 강조 `#087f8b`(accent), 회색 `#7a8a9b`(dataMuted), 실패 `#b42318`(danger). 렌더러가 이 값을 CSS 변수로 바꿔 다크 모드를 따르게 한다. 색을 지정하지 않으면 범주 팔레트(cat1–cat5)가 순서대로 쓰인다. 토큰 밖의 hex(예전 Tailwind 색 대응표 `src/lib/chart-colors.mjs`에 없는 값)는 빌드 경고다. 범주를 색으로 구분해야 하면 최대 4개, 계열이 6개 이상이면 경고이며 차트를 다시 설계한다.
- **라벨**: 범례보다 선·막대 옆 직접 라벨. 라벨을 회전하지 않는다. 핵심 지점 하나에 `markLine`이나 `markPoint`로 주석을 단다.
- **축**: 이중 y축을 쓰지 않는다(빌드 경고). 두 척도를 비교해야 하면 작은 차트 두 개로 나눈다.
- **로그 눈금**: 전후 감소·비율을 보여 주는 비교에는 선형 눈금을 쓴다. 바꾼 뒤 값이 막대로 거의 안 보이면 그것이 사실 그대로의 비율이다. 값 범위가 몇 자릿수에 걸쳐 선형으로는 읽을 수 없을 때만 로그를 쓰고, 그때는 축 이름(예: `"name": "CPU 초(로그 눈금)"`)과 캡션에 「로그 눈금」을 밝히고 정확한 값은 마크다운 표로 함께 준다. 선형 비교에서 작은 값이 막대로 안 보일 때도 정확한 값 표를 그림 바로 아래에 둔다. 렌더러가 모든 차트 밑에 붙이는 접힌 「데이터 표」(`<details>`)는 접근성 대체라 이 표를 대신하지 않는다.
- **로그 축에는 막대를 쓰지 않는다**: ECharts는 로그 축 막대를 1에서 자라게 그려, 1보다 작은 값은 거꾸로 자라고 길이가 비율처럼 읽힌다. 로그 축 + bar 시리즈는 빌드가 실패한다(`src/lib/visuals.mjs`). 로그가 맞는 범주별 값은 점(scatter, `[값, "범주"]`)으로 그린다.
- **휴대폰**: 렌더러가 720px·360px 두 벌의 정적 SVG를 만들고, 화면에 들어온 뒤 브라우저의 ECharts도 같은 배치(`narrowChartOption`)를 쓴다. 360px 판에서는 범주형 세로 막대가 가로 막대로 바뀌고 축 이름은 그림 아래 "가로축: …"으로 옮겨진다. 그래도 긴 범주 이름은 줄여서 쓴다.

## 데이터 형태별 시작점

| 데이터 | 권장 시작점 |
|---|---|
| 범주별 값 | 가로 bar |
| 시간·순서의 변화 | line |
| 부분/전체 비율 | stacked bar(파이·도넛은 3조각 이하일 때만) |
| 두 수치의 관계 | scatter |
| 전후 비교 | 같은 선형 축의 bar 두 계열 또는 slope, 정확한 값 표 |
| 값 범위가 몇 자릿수 | 선형으로 읽을 수 없을 때만 log 축; 축 이름·캡션에 「로그 눈금」, 정확한 값 표, 0·음수 처리 확인 |

## 렌더러

차트는 기본으로 인터랙션이 된다. 빌드 때 만든 정적 SVG(`src/lib/chart-render.mjs`, 720·360px)는 JavaScript가 없을 때와 첫 화면(레이아웃 흔들림 방지)용 대체이고, 차트가 화면 가까이 오면 브라우저가 같은 option과 색으로 ECharts(`src/lib/chart-live.ts`)를 그려 툴팁 · 범례 클릭이 된다. 라이트/다크 전환 · 폭 변화 · 움직임 줄이기 설정을 따른다. ECharts는 차트가 있는 글에서만 불러온다(br 약 171KB, 차트마다 option 수백 바이트). 표기:

```markdown
{{< chart caption="단계별 누적 지연" kind="실측" source="https://example.com/bench" id="fig-latency" height="360px" >}}
{ …JSON ECharts option… }
{{< /chart >}}
```

- `caption`·`kind`(필수): `kind`는 `실측` · `문헌값` · `설명용 가정` · `개념도` · `재구성` · `스크린샷` 중 하나. 새 글에서 빠지면 `npm test`가 실패한다. 캡션 문장에 성격 접두어를 쓰지 않는다.
- `source`: 출처 URL 또는 짧은 설명. `id`: `[[fig-latency]]`로 본문에서 "그림 N"을 가리킬 때.
- `interactive="false"`(선택): 그 차트만 정지 SVG로 둔다. 기본값은 켬이라 보통 쓰지 않는다.
- 툴팁: option에 `tooltip`이 없어도 기본으로 붙는다(막대·선이 있으면 axis, 산점도·파이·깔때기만 있으면 item). option에 `tooltip`을 쓰면 그 키가 우선한다. JSON이라 함수는 못 쓴다 — `valueFormatter`는 `"function(v){return v + '%'}"` 같은 단위 붙이기만 해석하고, 다른 함수 문자열은 버린다.
- 내부는 JavaScript 함수가 아닌 JSON으로 파싱 가능한 ECharts option이어야 한다. 렌더러가 지원하지 않는 속성을 있다고 가정하지 않는다.

추천 요청은 위치·이유·config를 반환한다. 적용 요청은 해당 글만 변경하고 빌드와 PC/모바일 렌더링, 다크/라이트 가독성을 확인한다. 실제 적용 권한이 이미 있으면 재승인을 요구하지 않는다.
