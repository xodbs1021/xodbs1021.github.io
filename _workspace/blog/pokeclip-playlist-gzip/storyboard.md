# 콘티 — 되감기 목록 gzip 글

## GzipGates (반복 영상 12초 · 360프레임 · 휴대폰판 있음)

주장 하나: CloudFront는 네 조건(경로 규칙의 compress · 캐시 정책의 gzip 허용 · 원본 Content-Length · 크기 1,000–10,000,000B)을 모두 지난 응답만 압축한다. 되감기 목록은 넷을 다 지나 gzip이 되고, 라이브 목록은 앞 둘을 켜더라도 Content-Length에서 막히고, 조각은 목록 규칙이 아니라 압축하지 않는 조각 규칙으로 간다.

배역(소재 없음 — 모두 코드로 그림)

| 무엇 | 모양 |
|---|---|
| 조건 넷 | 열 머리(①–④ + 이름) 아래 세 줄을 가로지르는 둥근 관문 칸 |
| 요청 셋 | 줄마다 왼쪽에서 오른쪽으로 가는 점과 지나온 만큼 칠해지는 선 |
| 결과 | 줄 끝 이름표(청록 gzip · 빨강 길이 없음 · 회색 압축 안 함)와 아래 회색 보조 글 |

| 프레임 | 무엇이 |
|---|---|
| 0–20 | 열 머리 넷 · 세 줄의 이름 · 관문 칸(빈 회색)이 나타남 |
| 20–140 | 1줄(되감기 목록 · /dvr/*.m3u8 규칙) 청록 점이 지나가며 관문 ①–④가 차례로 청록 ✓. 지나면 「gzip」 이름표 · 「138→5.5KB」 |
| 140–230 | 2줄(라이브 목록 · 켜더라도) 관문 ①② 는 점선 청록 ✓(지금은 꺼 둠 — 켠다고 치면), 점이 ③ 앞에서 멈추며 점 · 선과 ③ 이 빨강 ✕ 로 바뀌고 「길이 없음」 이름표 · 「chunked」 |
| 230–300 | 3줄(조각 · /dvr/* 규칙) 관문 칸은 처음부터 점선 회색 「–」, 회색 점이 그대로 지나 「압축 안 함」 회색 이름표 · 「목록 규칙 밖」 |
| 300–360 | 정지(포스터 340) |

- 138→5.5KB 는 재측정 `measure/raw/size.md` 의 s08_gap1(137,945B → gzip -6 5,497B)이다. 글 본문 수치와 같다.
- 라이브 줄의 ①② 를 점선으로 둔 까닭: 지금 `/live/*.m3u8` 규칙은 compress 를 꺼 두었다. 켜더라도 ③ 에서 막힌다는 것이 주장이라 「켜더라도」 를 줄 이름에 쓴다.
- kind=개념도(크기 숫자 하나는 이름표). 휴대폰판: 열 머리를 위 범례 두 줄(48px)로 옮기고 관문은 번호만.
- 요청은 글자 꾸러미가 아니라 점으로 그린다. 휴대폰판의 관문 사이(50px)에 글자 꾸러미가 들어가지 않는다.
