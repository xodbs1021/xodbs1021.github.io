# storyboard — pokeclip-nginx-playback-request-boundary

## 영상 1 PlaybackQueryGuard (반복 12초 = 360프레임, 휴대폰판)

주장: nginx는 경로의 방송과 쿼리의 방송이 같을 때만 재생 서버(:9996)로 넘기고, 다른 방송 · 중복 path · 인코딩한 키 · 인코딩한 슬래시 요청은 관문에서 403으로 돌려보내 상류에 하나도 닿지 않는다.

배치(데스크톱): 왼쪽에 요청 다섯 줄(고정폭 글자 상자), 가운데 세로 관문 「nginx」, 오른쪽 위 「재생 서버 :9996」 상자(첫 줄 높이). 각 요청 줄에서 관문까지 흐린 길.

1. `/A/list?path=A` — 통과
2. `/A/list?path=B` — 403
3. `/A/list?path=A&path=B` — 403(중복 path)
4. `/A/list?pa%74h=B&path=A` — 403(인코딩한 키)
5. `/A/..%2fB/list` — 403(인코딩한 슬래시)

| 프레임 | 무엇 |
|---|---|
| 0–15 | 요청 다섯 · 관문 · 재생 서버 상자 등장 |
| 20–58 | 1번 점이 관문에 닿고(40) 관문을 지나 재생 서버까지 강조색 선 + 화살촉. 1번 상자 강조색 |
| 86–116 | 2번 점이 관문에서 멈춤 → 길 빨강, 관문 앞에 「403」, 상자 빨강 |
| 134–164 | 3번 같은 방식 |
| 182–212 | 4번 같은 방식 |
| 230–260 | 5번 같은 방식 |
| 276–288 | 관문 오른쪽에 2–5번을 묶는 괄호 + 「상류 도달 0」 |
| 288–360 | 끝 프레임 유지(포스터 345) |

끝 프레임: 1번만 강조색 선으로 재생 서버에 닿고, 2–5번은 빨간 상자 · 관문 앞 「403」, 관문 너머 빈 자리에 괄호로 묶인 「상류 도달 0」. 혼자서도 「넷은 nginx에서 403으로 멈추고 상류엔 하나도 안 갔다」가 읽혀야 한다.

- 색: 대기 = ink, 통과 = accent, 거절 = danger, 괄호 = muted.
- 요청 글자는 고정폭(`MONO`), 줄여 쓰지 않는다. 관리 API(9997)는 넣지 않는다.
- 휴대폰판(1080×1350): 가장 긴 요청(23자)이 48px로 한 줄을 거의 다 쓰므로 세로로 쌓는다 — 위에서부터 재생 서버 상자, 가로 관문 「nginx」, 요청 다섯 줄. 요청 점은 줄 오른쪽 세로 길(x 980)을 타고 위로 올라 관문 아래에 닿는다. 1번만 관문을 지나 재생 서버까지 강조색 선. 거절된 요청은 빨간 길과 멈춘 점을 10프레임 보인 뒤 길을 지우고(403 자리를 지나므로) 요청 오른쪽에 「403」을 띄운다. 「상류 도달 0」은 403 열 바로 아래.
