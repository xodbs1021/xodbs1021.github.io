# storyboard — pokeclip-six-track-input-contract

## 영상 1 SixTrackFunnel (반복 약 11초 = 330프레임, 휴대폰판)

주장: 소스가 늘 때마다 트랙을 늘리는 원안(믹서 우회, 소스 약 10개 → 트랙 약 10개)을 버리고, OBS 믹서 6칸(트랙 1 = 본방 믹스, 트랙 2–6 = 소스별)에 모았다. 서버 이름은 audio1–audio6.

| 프레임 | 무엇 |
|---|---|
| 0–15 | 제목 「소스마다 트랙 하나?」 |
| 15–110 | 왼쪽에 소스 칩 10개가 하나씩 뜬다: 마이크 · 게임 · 디스코드 · BGM · 알림 · 브라우저 · 미디어 · 데스크탑 · 인트로 영상 · 효과음. 칩마다 오른쪽 자기 트랙 칸(회색 점선, 「트랙 1」…「트랙 10」)으로 선이 그어진다. 7–10번 칸은 빨간 점선. |
| 110–140 | 「믹서 우회 · 직접 후킹」(muted) · 빨간 Tag 「OBS 믹서 밖」 (7–10칸 옆) |
| 150–175 | 점선 칸 10개가 흐려지며 사라지고, 같은 자리에 OBS 믹서 상자(6칸)가 선다. 제목이 「OBS 믹서 6칸에 모은다」로 바뀐다. |
| 175–250 | 모든 소스 칩에서 가는 선이 트랙 1 「본방 믹스」(강조색, 굵게)로 모인다. 이어서 마이크 → 트랙 2, 게임 → 트랙 3, 디스코드 → 트랙 4, BGM → 트랙 5, 나머지 6개(알림 · 브라우저 · 미디어 · 데스크탑 · 인트로 영상 · 효과음) → 트랙 6 「기타」로 선이 이어진다. |
| 250–290 | 칸 오른쪽에 서버 이름 Tag 「audio1」…「audio6」(audio1만 강조색) |
| 290–330 | 포스터(끝 프레임) 유지: 끝에 Tag 「믹스 1 + 소스별 5」 |

끝 프레임(posterFrame 320): 소스 10개 → OBS 믹서 6칸 → audio1–6. 혼자서도 「10개를 6칸에 모았다」가 읽혀야 한다.

- 색: COLOR 만. 원안 칸 = muted 점선, 7–10칸 = danger 점선, 트랙 1 = accent, 나머지 = ink.
- 휴대폰판(1080×1350): 소스 칩을 위쪽 2열 5행 격자로, 트랙 칸을 아래쪽 세로 목록으로. 원안 단계는 칸 10개 대신 「트랙 1 … 트랙 10」 세로 칸을 작게(2열) 보여도 되고, 「트랙 10개」 한 상자 + 빨간 Tag 로 줄여도 된다. 글자 48px 이상.
- 소재 그림 없음(코드 도형만).

## 그림 2 소비처 도식(Mermaid flowchart TB, 폭 ≤ 440px)

OBS 트랙 1–6 → 서버 audio1–6 → 되감기 재포장(audio1만) / 편집기 미리듣기·렌더(6개 모두, trackId 0–5). audio1 경로만 강조.
