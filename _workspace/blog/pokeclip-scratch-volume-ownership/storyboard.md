# storyboard — pokeclip-scratch-volume-ownership

## 영상 1 VolumeFirstCopy (반복 9초 = 270프레임, 휴대폰판)

주장: Docker는 빈 named volume을 처음 붙일 때만 이미지의 같은 경로 내용을 소유권까지 볼륨으로 복사한다. 이미지에 경로가 없으면 볼륨이 root 소유로 남고, 이미 데이터가 있는 볼륨에는 이미지 변경이 반영되지 않는다.
근거: [Docker 볼륨 문서](https://docs.docker.com/engine/storage/volumes/#mounting-a-volume-over-existing-data).

같은 형태의 세 칸(데스크톱 열 셋, 휴대폰 행 셋). 칸마다 위 「이미지」 상자 → 복사 화살표 → 「볼륨」 상자(소유자 이름표) ← 「녹화기 UID 10002」 쓰기 화살표 → 결과 이름표.

1. 이미지 「경로 없음」(점선 회색 상자) · 볼륨 「비어 있음」 → 회색 점선 화살표 「복사할 것 없음」 → 소유 「root:root」 → 쓰기 화살표 빨강, 볼륨 테두리 빨강, 「쓰기 실패」.
2. 이미지 「빈 디렉터리 10002」 · 볼륨 「비어 있음」 → 강조색 화살표를 따라 점이 볼륨까지 내려감 「소유권 복사」 → 소유 「10002」(강조색) → 쓰기 화살표 강조색, 볼륨 테두리 강조색, 「쓰기 성공」.
3. 이미지 「빈 디렉터리 10002」 · 볼륨 「이전 데이터 있음」 → 회색 화살표가 막대에서 막히고 점이 막대 앞에서 사라짐 「복사 안 함」 → 소유 「그대로」(회색) → 쓰기 화살표 회색 점선, 「이미지 변경 반영 안 됨」(휴대폰 「이미지 미반영」).

| 프레임 | 무엇 |
|---|---|
| 0–15 | 제목 · 세 칸의 상자(이미지 · 볼륨 · 녹화기) 등장 |
| 25–56 | 복사 화살표가 그려지고 점이 내려감(1번은 점 없음, 3번은 막대 앞에서 멈춤) |
| 50–62 | 복사 이름표 「복사할 것 없음」 · 「소유권 복사」 · 「복사 안 함」 |
| 64–76 | 볼륨 소유자 이름표 「소유 root:root」 · 「소유 10002」 · 「소유 그대로」, 110까지 멈춤 |
| 110–132 | 녹화기에서 볼륨으로 쓰기 화살표 |
| 136–148 | 결과: 1번 빨강 「쓰기 실패」, 2번 강조색 「쓰기 성공」, 3번 회색 「이미지 변경 반영 안 됨」 |
| 148–270 | 끝 프레임 유지(포스터 프레임 250) |

끝 프레임: 세 칸이 나란히 — 빈 볼륨 + 경로 없음은 root:root 로 쓰기 실패, 빈 볼륨 + 10002 디렉터리는 10002 소유로 쓰기 성공, 데이터가 있는 볼륨은 복사가 막혀 이미지 변경이 반영되지 않음. 혼자서도 「빈 볼륨일 때만 소유권이 복사된다」가 읽혀야 한다.

- 색: 정상 = ink, 성공 · 복사 = accent, 실패 = danger, 막힘 · 보조 = muted.
- 휴대폰판: 칸을 행으로. 이미지 · 볼륨 상자는 이름과 상태를 한 줄에, 녹화기는 볼륨 오른쪽, 결과 이름표는 녹화기 위. 글자 48px 이상.
- 새 수치 없음(UID 10002 는 글 본문 값).
