# storyboard — pokeclip-dependency-upgrade-contracts

## 영상 1 HlsSessionAfterCut (반복 11초 = 330프레임, 휴대폰판)

절: 「세션이 살아 있어도 송출이 끊기면 30초 동안 404가 나옵니다」. kind=개념도 — PR #217 실측값을 옮긴 개념도.

주장: MediaMTX v1.21.1 계열에서 유효한 HLS 세션을 가진 플레이어가 송출을 끊은 뒤에도 같은 주소를 계속 요청하면, +1–10초는 200, +11–40초는 404(세션은 살아 있음), +41초부터는 401을 받는다. 404 창은 30초다.

구성(위 → 아래):
- 제목 「송출을 끊은 뒤 같은 HLS 세션이 받는 응답」
- 0초 지점에 「송출 끊음」 이름표(ink)와 시간축까지 내려오는 점선. 404 구간 위 가운데(25초 자리)에 「세션은 살아 있음」 이름표(ink).
- 「요청」 줄: 1 · 3 · … · 49초마다 점 하나(같은 주소를 계속 요청). 점 색은 그때 받은 응답 — 200 ink, 404 danger, 401 muted.
- 「응답」 줄: 0–10초 「200」 칸(ink 테두리), 10–40초 「404」 칸(danger), 40–50초 「401」 칸(muted 점선).
- 가로 시간축: 실제 초에 비례(0–50초), 눈금은 0초 · 10초 · 40초만, 오른쪽 끝은 화살표(401이 계속됨).
- 끝: 10–40초 아래 danger 괄호와 「404 창 30초」 이름표(danger).

| 프레임 | 무엇 |
|---|---|
| 0–15 | 제목 · 줄 이름 · 시간축 등장 |
| 8–20 | 「송출 끊음」 이름표 · 점선 |
| 25–245 | 재생점(accent)이 0초에서 50초까지 고르게 훑는다(실제 1초 = 4.4프레임). 지나간 만큼 요청 점이 찍히고 응답 칸이 드러난다. 응답 코드는 드러난 부분 가운데에 뜬다. 200 구간 약 1.5초, 404 구간 약 4.4초, 401 구간 약 1.5초 |
| 140–152 | 재생점이 404 구간 가운데(약 26초)를 지날 때 「세션은 살아 있음」 |
| 245–257 | 재생점 사라짐 |
| 255–270 | 「404 창 30초」 괄호 · 이름표 |
| 270–330 | 끝 프레임 유지(포스터 프레임 320) |

끝 프레임: 송출 끊음 표시, 요청 점 25개(색 3단), 200 · 404 · 401 세 칸, 0 · 10 · 40초 눈금, 「세션은 살아 있음」, 「404 창 30초」. 혼자서도 「세션이 살아 있는데 송출이 끊기면 30초 동안 404가 나온다」가 읽혀야 한다.

- 색: 정상 = ink, 재생점 = accent, 404 = danger, 401 = muted.
- 숫자는 200 · 404 · 401 · 0초 · 10초 · 40초 · 30초만 쓴다(근거 수치 밖의 숫자 금지).
- 휴대폰판(1080×1350): 제목 두 줄, 줄 이름(요청 · 응답)을 각 줄 위에 두고 0초 점선 오른쪽에 놓는다. 재생점은 줄 이름과 겹치지 않게 응답 칸 위에서 시작한다. 글자 48px 이상.
