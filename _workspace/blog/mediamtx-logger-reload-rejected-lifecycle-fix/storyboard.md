# storyboard — ReloadWaitCycle (11초, 330프레임, 반복, 휴대폰판 있음)

주장: #6206에서는 로그 재설정이 API를 닫은 뒤 훅이 끝나기를 기다린다. 그 훅이 재설정을 일으키고 새 설정의 API를 기다리는 훅이면 둘이 서로를 기다린다. v1.21.3은 로거를 다시 읽기만 하고 훅을 기다리지 않는다. 훅은 AI가 만든 재현용(「API가 돌아오기를 기다리는 훅」)이고, 리뷰어가 말한 교착을 만드는 한 방법이다.

- 0–0.5초: 위 줄(#6206)과 아래 줄(v1.21.3)에 훅 · 재설정 · API 상자.
- 위 줄 0.7초: 훅 → 재설정 `PATCH logLevel`.
- 1.7초: 재설정 → API `닫음`, API 회색 점선 「API 닫힘」.
- 2.7초: 재설정 → 훅 빨간 점선 「끝나길 기다림」, 재설정 「훅 대기」.
- 3.7초: 훅 → API 빨간 점선 「새 설정의 API를 기다림」, 훅 「API 대기」.
- 4.7초: 훅 · 재설정 빨강, 「서로 기다림」 이름표.
- 아래 줄(제목 「v1.21.3 · 재설정이 훅을 기다리지 않음」) 6.2초: `PATCH`. 7초: 재설정 「로거 다시 읽음」, API 「바로 다시 열림」. 7.8초: 훅 → API 청록 「응답 받음」. 8.7초: 훅 청록 「끝남」, 「기다림 없음」.
- 9–11초: 정지(끝 프레임 = 포스터, 320).
휴대폰판: 줄마다 재설정을 위, 훅 · API를 아래 양쪽(삼각형), 라벨은 PATCH · 기다림 · 닫음 · API 기다림 · 응답으로 줄임. 글자 48px 이상.

주의: v1.21.3도 logLevel을 바꾸면 경로 관리자 · RTSP · API를 다시 만든다(재측정 확인). 그래서 아래 줄의 API는 「열린 채」가 아니라 「바로 다시 열림」으로 쓴다(재측정에서 닫힘 약 2ms).
