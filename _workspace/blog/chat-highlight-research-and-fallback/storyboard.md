# storyboard — chat-highlight-research-and-fallback

## 영상 1 ChatSpikeToCard (반복 12초 = 360프레임, 휴대폰판)

주장: 채팅 급증 카드 하나가 만들어지는 순서. 5초 창 메시지 수가 최근 15분 중앙값 × 3 이상이고 10건 이상이면 급증, 20초 안의 급증 창은 한 사건, 첫 급증 창의 위치를 −3.9초 옮겨 영상 위치로, 앞 15초 · 뒤 5초를 붙여 카드 구간. 손으로 표시한 카드도 같은 카드 목록에 들어온다.

배치(데스크톱): 왼쪽 위 「채팅 시각」 축(5초 창 막대 16개), 그 아래 「영상 위치」 축, 오른쪽 「카드 목록」 판.
막대 값은 설명용(기준선 6, 급증 22 · 26 · 20, 2배쯤인 14 하나는 선 아래).

| 프레임 | 무엇 |
|---|---|
| 0–80 | 「채팅 시각」 제목, 막대가 왼쪽부터 자란다 |
| 80–120 | 점선 기준선 「최근 15분 중앙값」(muted), 실선 「중앙값 × 3」, 오른쪽 이름표 「10건 이상」 |
| 120–150 | 선을 넘은 막대 셋이 강조색으로 바뀐다(14 짜리는 그대로) |
| 150–185 | 급증 막대 위에 괄호, 「20초 안 → 한 사건」 |
| 185–225 | 첫 급증 창 시작에서 아래 「영상 위치」 축으로 화살표, 이름표 「− 3.9초」 |
| 225–265 | 영상 축의 사건 구간이 왼쪽으로 15초 · 오른쪽으로 5초 늘어 카드 구간이 된다(이름표 「앞 15초」 「뒤 5초」) |
| 265–300 | 카드가 오른쪽 「카드 목록」으로 날아가 「자동 · 채팅 급증」 카드가 된다 |
| 285–315 | 「핫키 · 손으로 표시」 카드가 같은 목록에 들어온다 |
| 315–360 | 끝 프레임 유지(posterFrame 340) |

끝 프레임: 막대 · 두 선 · 강조된 급증 셋 · 괄호 · −3.9초 화살표 · 카드 구간 · 목록의 카드 두 장. 혼자서도 「급증 판정 → 묶기 → 영상 위치 → 카드, 수동 카드도 같은 목록」이 읽혀야 한다.

- 색: 막대 = ink(옅게), 급증 = accent, 기준선 = muted 점선, 임계선 = ink, 카드 = accent, 핫키 카드 = ink 테두리.
- 휴대폰판(1080×1350): 채팅 축 → 영상 축 → 카드 목록(두 장 나란히)을 세로로 쌓는다. 글자 48px.

## 그림 2 카드가 생기는 두 경로(Mermaid flowchart TB, 폭 ≤ 440px)

채팅 수집 서버 → chat_messages → chat-detector(5초 창 · 15분 중앙값 판정) → 수집 서버 위치 변환(−3.9초) → 클립 서버 카드 표(auto). OBS 핫키 · 웹 수동 표시 → 클립 서버 카드 표(hotkey). 카드 표 → 편집기. 강조는 수동 경로.
