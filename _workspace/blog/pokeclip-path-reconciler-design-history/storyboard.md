# storyboard — pokeclip-path-reconciler-design-history

## 영상 1 AuthQueueSerial (반복 11초 = 330프레임, 휴대폰판)

주장: 대안 T(연결마다 인증)에서는 송출 연결 10개가 동시에 들어와도 HTTP 인증 응답을 한 줄로 하나씩 기다려, 첫 연결은 약 0.3초 · 열 번째 연결은 3.057초에 수락되고, 새 HLS 세션 · 목록 API 요청도 같은 줄에서 기다린다.

근거: 10월 5일 로컬 실측(MediaMTX 1.21.1, 인증 응답에 0.3초 지연을 넣은 스텁). 그림에 쓰는 숫자는 0.3초 · 3.057초 · 10개뿐이다. 시간은 0–3.057초에 비례해 그린다(인증 한 번 = 3.057 / 10 초 = 19.5프레임).

위쪽(왼 → 오): 「송출 연결 10개」 칸 10개(5×2) → 「인증」 관문(한 칸만 들어감, 아래 작은 막대가 0.3초를 채움, 밑에 「하나씩 0.3초」) → 「수락」 칸 10개(5×2).
가운데: 같은 줄 끝에 「새 HLS 세션」 · 「목록 API」 상자 둘, 관문 쪽 점선 화살표.
아래: 「수락 시각」 축(0 → 3.057초, 비례). 막대가 시간에 맞춰 차고, 연결이 수락될 때마다 눈금이 하나씩 선다. 첫 눈금 아래 「0.3초」, 마지막 눈금 아래 「3.057초」(강조 이름표).

| 프레임 | 무엇 |
|---|---|
| 0–15 | 제목 · 이름표 · 빈 칸 · 관문 · 축 등장 |
| 8–26 | 연결 1–10이 왼쪽에서 한꺼번에 미끄러져 들어온다(동시 도착) |
| 34–229 | 연결이 하나씩 관문에 들어가 19.5프레임(0.3초 비례) 머문 뒤 수락 칸으로 간다. 관문은 강조색. 축 막대가 0 → 3.057초로 차고, 수락마다 눈금. 53프레임에 「0.3초」 |
| 229 | 열 번째 수락, 「3.057초」 이름표 |
| 229–262 | 멈춤(1.1초) |
| 262–276 | 「새 HLS 세션」 · 「목록 API」가 줄 끝(연결 칸 아래)에 들어온다(muted 점선) |
| 276–288 | 두 상자가 danger로 바뀌고 관문 쪽 점선 화살표 + 「새 HLS 세션 · 목록 API도 대기」(danger) |
| 288–329 | 끝 프레임 유지(1.4초, 포스터 320) |

끝 프레임: 연결 칸은 비고, 수락 칸 10개가 차 있고, 축 끝에 「3.057초」 · 시작 쪽 「0.3초」, 줄 끝에 빨간 「새 HLS 세션 · 목록 API도 대기」. 혼자서도 「연결마다 인증하면 하나씩 기다려 열 번째는 3.057초, 다른 요청도 같은 줄에서 기다린다」가 읽혀야 한다.

- 색: 줄 선 연결 = ink, 관문 안 · 수락 = accent, 줄 끝에서 기다리는 요청 = danger(등장 직후는 muted), 보조 글자 = muted.
- 휴대폰판: 연결 칸(왼쪽 위) · 관문(오른쪽 위) · 그 아래 요청 둘과 이름표 · 수락 칸(오른쪽, 관문에서 아래 화살표) · 맨 아래 축. 축의 「0」은 「0.3초」와 겹쳐 뺀다. 글자 48px 이상.
- 캡션 제안: 「연결마다 인증하면 동시에 들어온 송출 10개가 인증 응답을 하나씩 기다려 열 번째는 3.057초에 수락되고, 새 HLS 세션과 목록 API도 같은 줄에서 기다린다(10월 5일 로컬 실측, 인증 응답 0.3초 지연 스텁).」
