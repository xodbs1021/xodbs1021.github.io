## 지시와 어긋나거나 보탤 것

- 끌어오기 방식 자체는 사용자가 골랐다(AI 권고안 B). AI 몫은 주기 · 예산 · 큐 같은 세부다.
- 설계는 10/2 한 번에 끝나지 않았다. 10/1 r1 → 10/2 r6 → 10/4 r7 → 10/5 r7.1.
- 상류에 독립 기능으로 내는 결정은 10/6 전환이 아니라 10/7 결정이다. 10/6은 연결별 인증으로 전환(판정 실패 시 새 연결 거부)을 정했고, 포크에 싣고 상류에 내는 것은 기존 방침을 따랐다.
- PDF 54쪽은 「13번의 인증 지연 주입(10접속 · 0.1/0.3초 → 마지막 수락 1.059/3.057초)은 당시 진단 기록으로 남깁니다」라고 적는다. 「CASE 13 · 계정별 경로 조정」 아래 「옛 reconciler는 연결별 인증으로 대체」와 같은 사례로 묶었고, 실험 대상이 연결별 인증안이라는 말은 없다. 조정자 계획에도 따로 「실시간 시험 지연 0.3초」(10/2)가 있었지만 조정자 단위 시험용이었고 실행된 적 없다. 혼동 원인일 수 있다.
- 지금 글의 틀린 곳: 29행 「Secrets Manager 이행은 현재도 준비 중」(10/6 머지 · 10/22 병행 종료), 43행 「10월 5일 … 원시 패킷과 로그를 다시 대조」(10/5는 실측 당일, 다시 대조한 날은 기록 없음), 55행 「dev-media 연동과 실제 서버 검증도 남아 있습니다」(10/19 통과), 17행 「설계와 실측은 AI 협업」은 맞지만 실험 대상이 조정자로 읽힘.
- 운영 상자 응답기 모드(11/4)는 공개 코드에 「제자리 교체」만 남아 있다. 모드 자체는 비공개 기록뿐이다(값을 넣는 tfvars는 저장소 밖).
- 「dev 상자 정지」 11/6은 미디어 상자만이다. 웹 dev 상자는 11/10에 따로 멈췄다.
