# storyboard — pokeclip-recording-defect-in-origin

## 영상 1 `DecodeRecovery` (12초 반복, 1920×1080 + 휴대폰판 1080×1350)

주장 하나: 결함 조각에서 재생을 이으려면 다시 붙인 뒤 다음 조각 시작으로 옮겨야 한다.

억지 판정: 독자가 볼 것은 재생점의 위치가 시간에 따라 어떻게 되는가(멈춤 / 같은 자리 되풀이 / 건너뛰어 이어짐)다. 둘째 줄의 「다시 붙이면 같은 자리에서 또 오류」는 되풀이 자체가 정보라 정지 그림보다 움직임이 맞다. 끝 프레임(포스터)은 세 결과를 함께 보여 줘 혼자서도 뜻이 통한다.

배치: 세 줄(위에서 그대로 둠 / recoverMediaError()만 / 다시 붙이고 다음 조각 시작으로). 줄마다 조각 1623·1624·1625·1626(길이 4·6·4·4초 비례). 데스크톱은 상태 이름표를 줄 이름 오른쪽, 휴대폰은 조각 아래.

| 프레임 | 무엇이 |
|---|---|
| 0–15 | 제목·줄·조각이 나타남 |
| 15–60 | 1줄 재생점이 1623 안(33.5초)에서 오류 자리(37.35초)로 이동 |
| 60 | 1624가 빨강, 재생점 빨강. 66부터 「그 자리에서 굳음 · 알림 없음」 |
| 80–125 | 2줄 같은 이동, 125에 오류 |
| 142·160·178 | 「↺ 다시 붙임 n/3」, 재생점이 1624 첫 키프레임(37.17초)에서 오류 자리로 다시 가 또 빨강 |
| 198 | 「같은 자리 오류 4번 → 덮개」, 재생점 흐려짐 |
| 210–250 | 3줄 같은 이동, 250에 오류 |

| 326–360 | 멈춤(포스터 350) |
