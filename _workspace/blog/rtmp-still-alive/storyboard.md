# rtmp-still-alive 콘티

## 영상 1 — ChunkInterleave (반복 11초, 330프레임 · 30fps, 휴대폰판 ChunkInterleaveMobile)

주장 하나: RTMP 는 큰 영상 메시지를 청크로 쪼개 보내므로, 그 사이에 작은 오디오 · 제어 메시지가 끼어들 수 있다
(Adobe RTMP 사양 5.3절, "to prevent large low-priority messages (such as video) from blocking smaller high-priority messages (such as audio or control)").

생성 소재 없음. 코드로만 그린다. 숫자는 「128바이트」 하나만.

### 배치 (데스크톱 1920×1080)

- 제목 이름표(위, y≈48): 「큰 영상 메시지 사이에 끼어드는 작은 메시지」.
- 가로 두 줄. 줄마다 위에서 아래로: 줄 이름 → 대기 자리(관 입구 위) → 관(같은 TCP 연결 하나) → 「받은 순서」 칸 → 결과 이름표.
  - 관 왼쪽 끝 상자 「OBS」, 오른쪽 끝 상자 「서버」. 관 안의 칸은 오른쪽으로 같은 속도로 흐르고, 서버 상자에 닿으면 사라진다.
  - 「받은 순서」 칸은 서버 아래 오른쪽 정렬. 메시지가 끝까지 다 도착한 순서대로 왼쪽부터 채운다.
- 1줄 「통째로 보내면」: 영상 메시지 막대 하나(관의 대부분을 차지, ink 테두리).
- 2줄 「청크로 쪼개면」: 같은 길이의 영상을 청크 6칸 V1–V6(같은 ink 테두리)으로. 순서 V1 V2 오디오 V3 V4 제어 V5 V6.
- 오디오 · 제어 칸은 두 줄 모두 accent.
- 아래 작은 이름표(muted): 「청크 크기 기본 128바이트 · Set Chunk Size로 바꿈」 (휴대폰판 생략).

### 순서 (프레임)

| 프레임 | 1줄 통째로 | 2줄 청크로 |
|---|---|---|
| 0–15 | 제목 · 상자 · 관 · 줄 이름 나타남 | 같음 |
| 20– | 영상 막대가 OBS 에서 관으로 들어가기 시작(속도 일정, 끝까지 같은 속도) | V1 부터 차례로 관에 들어감 |
| ≈30 | 오디오가 관 입구 위 대기 자리에 나타남 | 같음 |
| ≈36 | danger 이름표 「기다림」 이 대기 칸 옆에 뜸 | — |
| ≈50–64 | 오디오 대기 | 오디오가 V2 바로 뒤로 내려와 끼어듦 |
| ≈56 | 제어가 대기 자리에 나타남 | 같음 |
| ≈92–106 | 제어 대기 | 제어가 V4 바로 뒤로 끼어듦 |
| ≈110–136 | 영상 막대가 다 들어간 뒤에야 오디오 · 제어가 내려와 관에 들어감, 「기다림」 사라짐 | V5 · V6 들어감 |
| ≈148– | — | V1 부터 서버에 다 도착 → 「받은 순서」 셋째 자리(점선 틀)에 조각이 하나씩 쌓임 |
| ≈178 | — | 오디오 다 도착 → 첫째 자리 |
| ≈220 | — | 제어 다 도착 → 둘째 자리, accent 이름표 「먼저 도착」 |
| ≈223 | 영상 메시지 다 도착 → 첫째 자리 | — |
| ≈250 | 오디오 · 제어 마지막에 도착 → 둘째 · 셋째 자리, danger 이름표 「영상 뒤에 도착」 | V6 도착 → 조각 여섯이 막대 하나 「영상 메시지」 로 합쳐짐(250–266) |
| 270–330 | 끝 상태 유지(2초) | 같음 |

속도는 판마다 「관 길이 + 줄 전체 길이」 를 프레임 20–250 에 지나도록 정한다(두 줄이 같은 속도라 도착 순서를 견줄 수 있다).

### 끝 프레임(포스터 = 320)

- 관 두 개는 비어 있다.
- 1줄 받은 순서: [영상 메시지][오디오][제어] + danger 「영상 뒤에 도착」 (오디오 · 제어 아래).
- 2줄 받은 순서: [오디오][제어][영상 메시지] + accent 「먼저 도착」 (오디오 · 제어 아래).
- 아래 「청크 크기 기본 128바이트 · Set Chunk Size로 바꿈」.

### 휴대폰판 (1080×1350)

- 제목 두 줄: 「큰 영상 메시지 사이에」 / 「끼어드는 작은 메시지」.
- 같은 두 줄을 위아래로, 글자 48px 이상. 관은 짧아지고 칸도 비례해 줄어든다(속도는 같은 프레임에 끝나도록 다시 계산).
- 128바이트 이름표는 생략.
