# evidence — pokeclip-srt-latency-late-retransmission (2편)

유형: 실험·벤치마크 + 의사결정. 1편(녹화 원본의 결함)에서 이어진다. 비공개 근거는 「볼트 실험 종합(비공개)」처럼 적고, 실험대 수치는 PR #493 공개 요약으로 근거화한다.

## 역할

- 작성자: 운영 경로 시험 방송으로 원인을 확정하자는 결정, latency 3초 결정(11-09 「3초로 올려」). 운영 미디어 서버의 시스템 로그·UDP 카운터 읽기와 시험 방송 동안의 SRT 통계 감시는 AI의 원격 실행이 자동 모드 분류기에 막혀 작성자가 읽기 전용으로 직접 실행.
- AI(Claude Code 오케스트레이터와 하위 에이전트): 실험 설계·실행·분석, 시험 방송의 OBS 송출 조작, PR 본문 작성.
- 리뷰: Claude Code·Codex.
- 팀원: 언급하지 않음.

## 시각 자료

- 그림 1(ECharts, 실측): 1차 방송 수신 RTT 10초 최댓값 선(회색) + 녹화기 오류 14건 점(위험색, 높이 = 직전 10초 최대 RTT) + latency 1초 점선(강조). 가로축은 송출 시작 뒤 분(시작 시각 KST는 캡션). 이중 축 대신 같은 단위(RTT 초)에 오류를 올렸다.
- 그림 2(Remotion `LateRetransmit`, 개념도, 11초 반복, 휴대폰판): 세 줄 비교. 급등 1.5초·재전송 도착 2.8초는 설명용 배치(storyboard.md).
- 표 2: 재정렬 오류(급등 모양 × latency), 복호 오류 조각(머문 시간 × 1,000/3,000ms). 정확한 값 조회라 표. 같은 수치를 그래프로 중복하지 않음.
- 넣지 않음: Wi-Fi 지표 그래프(값 몇 개라 문장), +2초 대 +4초 비교(값 2개라 문장), Mermaid 구성도(노드가 적은 직선 흐름), 생성 이미지.
