## WildcardMatch(반복 영상 10초 · 300프레임 · 휴대폰판 있음)

글의 주장 하나: **정책 Resource 의 `*` 는 경로 구분자(`/`)와 쿼리(`?`)를 가리지 않고 아무 글자나 먹는다** — 그래서 앞 `*` 하나짜리 정책이 남의 방송 주소에 맞았고, 종류를 고정한 정책은 맞지 않는다.

같은 요청 문자열 `{base}/live/B/index.m3u8?x=/A/` 를 두 줄에서 쓴다(A = 내 방송, B = 남의 방송 — 지어낸 값).

| 시각 | 무엇이 |
|---|---|
| 0–0.7초 | 위 줄: 정책 `{base}/*/A/*` 와 그 아래 요청 문자열이 뜬다 |
| 0.7–2.7초 | 정책의 첫 `*` 가 청록으로 칠해지고, 요청의 `live/B/index.m3u8?x=` 20글자가 왼쪽부터 청록 바탕으로 차오른다(「* 가 먹음」) |
| 2.7–3.3초 | `/A/` 가 정책의 `/A/` 와 맞물려 굵어진다. 끝 `*` 는 빈 글자 |
| 3.3–4.5초 | 빨간 이름표 「일치 · 남의 방송이 열림」 |
| 4.5–5.2초 | 아래 줄: 정책 `{base}/live/A/*` 와 같은 요청이 뜬다 |
| 5.2–6.5초 | `{base}/live/` 가 왼쪽부터 맞물리고, `B` 칸이 빨강(정책은 `A`) |
| 6.5–10초 | 청록 이름표 「불일치 · 403」. 두 줄이 모두 머문다 |

끝 프레임(포스터, 280): 두 줄 결과가 다 보인다.

- 수치 없음, 규칙은 AWS 문서 문장 그대로 → `kind="개념도"`. 재측정 `measure/raw/wildcard.tsv` 의 「앞 * 가 먹은 글자」 칸과 같은 글자를 쓴다.
- 휴대폰판: 같은 두 줄을 세로로 쌓고 고정폭 글자 50px · 이름표 48px.
