# 콘티 — aws-gcp-bidirectional-cutover-experiment

## 영상 1 — CutoverQueuePause (반복 클립 10초, 300프레임 @30fps, kind 개념도)

주장 하나: 전환하는 동안 사용자 요청은 거절되지 않고 접수 큐에 쌓였다가, 전환이 끝나면 쌓인 것부터 대상(GCP)으로 넘어간다.

배역(코드 부품만, 생성 소재 없음): 트래픽 봇 · 접수 큐 · AWS 앱 · RDS · GCP 앱 · Cloud SQL — `Node` 상자. 요청 = `FlowPath` 패킷. 쌓인 요청 = 접수 큐 상자 안의 작은 사각형 줄.

| 구간 | 프레임(초) | 무엇이 · 어떻게 |
|---|---|---|
| 1 전환 전 | 0–75 (0–2.5) | 봇 → 접수 큐(회색 선) → AWS 앱(강조 선)으로 패킷이 흐른다. AWS 앱 · RDS 강조. GCP 쪽은 회색. 이름표 「전환 전」. |
| 2 전환 중 | 75–180 (2.5–6) | 이름표 「전환 중 · 전달 멈춤」. AWS 경로가 흐려지고 패킷이 멈춘다. AWS 앱은 점선 회색(일시정지 — 실패 아님, danger 색 쓰지 않음). 봇 → 접수 큐는 계속 흐르고 큐 안 사각형이 1→7개로 쌓인다. 이름표 「가장 긴 대기 8.2초(실측)」 — 본문의 8,249ms. |
| 3 전환 뒤 | 180–240 (6–8) | GCP 경로가 강조색으로 그려지고, 쌓인 사각형이 줄어들며 패킷이 몰려 GCP 앱으로 흐른다. GCP 앱 · Cloud SQL 강조. |
| 끝 | 240–300 (8–10) | 정지 유지 2초. 이름표 「쌓인 요청부터 GCP로」. |

끝 프레임(포스터, 290): GCP 경로 강조 · 패킷이 GCP 앱으로 흐름 · 「쌓인 요청부터 GCP로」 · 「가장 긴 대기 8.2초(실측)」. 혼자서도 「요청이 큐를 거쳐 GCP로 넘어갔다」가 읽힌다.
