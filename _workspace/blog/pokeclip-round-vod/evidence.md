# evidence — pokeclip-round-vod (3편)

유형: 의사결정 + 설계(트러블슈팅 도입). 1편(녹화 원본 결함) · 2편(SRT latency)과 같은 시리즈. 비공개 근거는 「팀 결정 기록(비공개)」 · 「실험 종합(비공개)」처럼 적고, 공개 근거는 PR #492 본문 · 공개 저장소 파일 · RFC · hls.js 소스로 연결한다.

## 역할

- 작성자: 처방 (가) 회차 단위 VOD 선택(11-04), 회차 문서 키 `.round` · 같은 호출 안 물러섬 · 앞 사슬 실패나 문서 없음이면 물러섬(11-04 추천안 승인), 회차 대기 상한 없이 30분 경고(11-08), 회차 번호 없는 옛 세션 머리 사슬은 한계 기록(11-08), 이미 끝난 회차 소급 안 함(11-04), PR 머지 실행(11-09), 운영 다시보기 재생 확인(11-10).
- AI(Claude Code 오케스트레이터와 하위 에이전트): 범위 조사 · 설계 · 계획 · 구현 · 실험 · PR 본문, 작성자 승인 뒤 운영 반영 작업.
- 리뷰: 커밋마다 Claude Code · Codex 듀얼.
- 웹: 회차 API 응답 필드 그대로라 이 PR 로 바뀐 웹 코드 0. 지난 방송 화면 VOD 이전은 별도 웹 작업.
- 팀원: 언급하지 않음.

## 시각 자료

- 그림 1(ECharts, 실측): 공개 골든 1,730조각의 EXTINF 전부. 앞 목록 회색 선 · 뒤 목록 강조 선 · 목표 길이 6초 점선(markLine) · seq 1627 위험색 점(markPoint). 데이터 범위 = 골든 전체(seq 4–1733, 잘림 없음, 익명화는 호스트 · 스트림 이름만). 이중 축 없음, 토큰 hex 셋만.
- 그림 2(Remotion `RoundDocument`, 개념도, 11초 반복, 휴대폰판): 고치기 전 · 뒤 두 줄. 띠 폭은 EXTINF 합 비례(storyboard.md).
- 표: 후보 넷(선택지 비교), decideScope 7줄(정확한 규칙 조회), 재생 시험 결과(목록 × 결과).
- 넣지 않음: 깨우기 흐름 Mermaid(본문 한 문장으로 충분), 지연 상한 수식, 변이 26개 표(수치 셋이면 문장), 생성 이미지.
