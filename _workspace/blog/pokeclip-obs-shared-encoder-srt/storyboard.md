# storyboard — pokeclip-obs-shared-encoder-srt

## 영상 1 SharedEncoderStart (반복 약 12초 = 360프레임, 휴대폰판)

주장: 본방 인코더를 나눠 쓰므로 GOP는 인코더가 만들어지기 직전에만 맞출 수 있고, 이미 돌고 있는 인코더면 SRT 시작을 거절하며, 본방이 멈추면 SRT도 같이 멈춘다.

위쪽: 시작 순서 상자 4개(왼→오, 화살표로 연결)
1. 「프로필 설정 적용」
2. 「STREAMING_STARTING」 (아래 작은 글자 「keyint 2」)
3. 「인코더 생성」
4. 「출력 시작」

아래쪽: 가운데 「x264 1개」 상자(인코더). 오른쪽으로 두 줄: 위 「RTMP → 치지직」, 아래 「SRT → PokeClip」. 두 줄 모두 인코더 상자 가장자리에서 시작.

| 프레임 | 무엇 |
|---|---|
| 0–15 | 상자들(회색) 등장 |
| 15–45 | 1번 상자 강조 |
| 45–85 | 2번 상자 강조 + Tag 「keyint_sec → 2」(강조색) |
| 85–115 | 3번 상자 강조, 아래 「x264 1개」 상자가 뜬다 |
| 115–165 | 4번 상자 강조, RTMP · SRT 두 줄로 같은 패킷이 동시에 흐른다(같은 색 점이 두 줄을 같은 박자로) |
| 165–215 | 「본방 정지」 Tag(ink) → RTMP 줄 패킷이 멈추고 회색, 같은 순간 SRT 줄도 회색 + Tag 「SRT도 함께 정지」 |
| 215–235 | 초기화(상자 회색으로). 인코더 상자 옆에 Tag 「녹화 중 · keyint ≠ 2」(muted) — 인코더 상자는 이미 켜진 상태(ink 테두리) |
| 235–290 | 1 → 2 순서로 다시 강조, 2번 상자에서 빨간 Tag 「실행 중 GOP 변경 불가」, 이어서 SRT 줄 끝에 빨간 Tag 「SRT 시작 거절」. RTMP 줄은 그대로 흐른다(본방은 계속). |
| 290–360 | 끝 프레임 유지(포스터 프레임 340) |

끝 프레임: 시작 순서 4칸, 2번 상자에 빨간 표시, 인코더 1개, RTMP 줄은 흐르고 SRT 줄은 빨간 「SRT 시작 거절」. 혼자서도 「인코더가 이미 돌면 SRT를 시작하지 않는다」가 읽혀야 한다.

- 색: 정상 = ink, 지금 단계 = accent, 거절 = danger, 멈춤 = muted.
- 휴대폰판: 시작 순서 상자를 세로 4줄로(위쪽 절반), 인코더 + 두 출력 줄을 아래쪽에. 글자 48px 이상.
- 「keyint」 · 「STREAMING_STARTING」 같은 코드 이름은 영문 그대로.

## 그림 2 구성도(Mermaid flowchart, TB, 폭 ≤ 440px)

OBS 본방 출력의 x264 인코더 1개 · 오디오 인코더 → (공유) → RTMP 본방 출력 / SRT 출력(MPEG-TS). SRT 출력의 접속 정보: 주소(srt://수신:8890?latency&pkt_size) · streamid(key 칸) · passphrase(password 칸, 별도 필드). 독 페이지(CEF) ⇄ 루프백 브리지(127.0.0.1, Bearer · Host · Origin 검사) ⇄ 플러그인 코어. passphrase 별도 필드를 강조.
