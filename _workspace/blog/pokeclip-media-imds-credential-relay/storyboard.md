# 콘티 — HopLimitRelay (반복 영상 12초 · 휴대폰판)

주장 하나: 홉 상한을 1로 내리면 IMDS 토큰 응답이 docker 브리지를 넘지 못하고, 호스트 망의 창구만 자격을 받아 토큰 파일이 있는 두 소비자에게만 건넨다.

성격: 개념도(수치 없음 — 홉 상한 1 · 2, 401은 이름표). 생성 소재 없음(상자 · 선 · 패킷은 코드).

| 구간(30fps) | 무엇이 | 모습 |
|---|---|---|
| 0–135(0–4.5초) | 단계 「홉 상한 2」 | IMDS → 브리지 안 세 컨테이너로 토큰 응답 패킷(위험색). 아래 이름표 「토큰 응답이 브리지를 건넘」 |
| 135–240(4.5–8초) | 단계 「홉 상한 1」 | 세 갈래가 흐려지고, 브리지 경계에서 멈추는 갈래 하나 + ✕. IMDS → 창구(호스트 망) 갈래가 강조색으로 이어짐. 이름표 「브리지를 건너면 TTL 0 — 버려짐」 |
| 240–360(8–12초) | 단계 「창구가 토큰 대조」 | 창구 → 사이드카 · janitor 패킷(강조색). MediaMTX · nginx → 창구 점선 요청 끝에 「401」. 이름표 「토큰 파일이 있는 둘만 자격」. 마지막 1초 이상 멈춤 |

끝 프레임(포스터, 350): 세 단계 이름표(지금 단계 강조), ✕ 와 401, 창구 → 두 소비자 선. 혼자 봐도 「IMDS는 창구까지만, 창구는 두 소비자에게만」 이 읽힌다.

배치
- 데스크톱(1920×1080): 왼쪽 IMDS · 가운데 「호스트 망」 칸 안 창구 · 오른쪽 「docker 브리지」 칸 안 MediaMTX · nginx / 사이드카 / janitor.
- 휴대폰(1080×1350): 왼쪽 위 IMDS, 왼쪽 아래 호스트 망 칸 안 창구, 오른쪽 브리지 칸 안 세 컨테이너 세로. 글자 48px 이상.
