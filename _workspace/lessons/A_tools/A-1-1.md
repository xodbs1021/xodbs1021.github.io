## 레벨 A-1 / 1강: 터미널이 뭐고 왜 써야 하는가 — GUI를 버려야 하는 순간들

---

### 시작 — 검은 창에 대한 오해부터 풀자

처음 백엔드 강의를 듣거나 AWS 콘솔에서 EC2 한 대를 띄우면 곧장 부딪치는 화면이 있다. 마우스가 안 통하는 새카만 창, 깜빡이는 커서 한 개. 많은 입문자가 여기서 한 번 멈칫한다. "이걸 어떻게 다뤄야 하지? 뭘 잘못 누르면 컴퓨터가 망가지지 않나?"

결론부터 말하면, 터미널은 **OS와 직접 한국어 대화 대신 명령어로 대화하는 채팅창**이다. 카카오톡에 메시지를 치면 상대가 답하듯, 터미널에 명령을 치면 운영체제가 답한다. 새 폴더 만들고 싶으면 "새 폴더 만들어 줘"를 명령어로 옮긴 것뿐.

이 강의가 끝나면 다음 3개를 할 수 있다.

1. 터미널·콘솔·셸·CLI 4개 용어를 한 문장으로 구분
2. GUI 10단계 작업을 CLI 한 줄로 대체하는 시연을 직접 따라하기
3. PokéClip EC2 서버에 SSH로 들어가 디버깅하는 첫 감각

PokéClip 프로젝트 맥락에서 한 번 더 강조하면, 우리가 곧 띄울 AWS EC2 SRT 서버에는 마우스가 없다. 더블클릭이 없다. SSH로 들어가서 터미널 한 창 띄우는 것이 전부. 그 환경에서 FFmpeg 디멀티플렉싱(다중 트랙 분리)을 디버깅해야 한다. 터미널 없이는 PokéClip이 한 발자국도 못 나간다.

### GUI vs CLI — 둘은 우열이 아니라 도구다

먼저 GUI와 CLI 두 단어를 정확히 짚는다.

- **GUI** (Graphical User Interface): 그래픽 기반 사용자 인터페이스. 우리가 매일 쓰는 Finder, 익스플로러, 크롬 브라우저, 카카오톡 모두 GUI.
- **CLI** (Command Line Interface): 명령줄 기반 사용자 인터페이스. 터미널에 명령을 한 줄씩 쳐서 컴퓨터와 대화.

| 비교 항목 | GUI | CLI |
|---|---|---|
| 발견성(discoverability) | 매우 높음 — 메뉴 보고 찾기 가능 | 낮음 — 명령을 알아야 함 |
| 표현력 | 제한적 — 버튼 종류만큼만 | 매우 높음 — 명령 조합 무한 |
| 자동화 | 어려움 — 클릭 시뮬레이션 필요 | 자연스러움 — 셸 스크립트 한 줄 |
| 원격 접근 | 무겁고 비쌈 — 화면 영상 전송 필요 | 가벼움 — 텍스트만 전송 (SSH) |
| 재현성 | 낮음 — "다음 누르고 그다음 누르고…" | 매우 높음 — 명령어 한 줄 복붙 |
| 학습 곡선 | 완만 | 가파름 (초기) |

핵심: **둘 중 하나가 우월한 게 아니다.** GUI는 "처음 보는 도구를 더듬어 찾을 때" 강하고, CLI는 "같은 작업을 100번 반복하거나 원격 서버에서 일할 때" 강하다. 백엔드 엔지니어가 CLI를 매일 쓰는 이유는 GUI가 못나서가 아니라, 백엔드 일의 80% 이상이 **자동화·원격·재현성**의 3박자 위에서 돌아가기 때문이다.

이 3박자를 머리에 새겨 두자. 시리즈 끝까지 다시 나온다.

### 용어 정리 — 터미널·콘솔·셸·CLI 4개의 진짜 의미

입문자가 가장 헷갈리는 4개 단어를 한 번에 정리한다. 회사에서 "셸 좀 띄워봐"와 "터미널 열어"가 같은 뜻으로 쓰여 헷갈리지만, 엄밀히는 다르다.

| 용어 | 의미 | 비유 |
|---|---|---|
| **터미널** (Terminal) | 텍스트 입출력을 받는 **창** 자체 (프로그램 또는 물리 장치) | 카카오톡 **채팅창** |
| **콘솔** (Console) | 컴퓨터 본체와 직접 연결된 입출력 장치. 요즘은 터미널과 거의 동의어로 쓰임 | 카카오톡 본사 메인 채팅창 |
| **셸** (Shell) | 사용자가 친 명령어를 해석해서 OS에 전달하는 **프로그램** (bash, zsh 등) | 카톡 상대방(번역가) |
| **CLI** (Command Line Interface) | 명령어로 상호작용하는 **인터페이스 방식** 자체 (개념) | "텍스트로 대화한다"는 **방식 자체** |

한 문장 요약:

> **터미널이라는 창** 안에서 **셸**이라는 프로그램이 돌고 있고, 사용자는 **CLI** 방식으로 그 셸과 대화한다. 콘솔은 옛날 물리 장치 이름이었지만 지금은 터미널과 거의 같은 뜻으로 통용된다.

다음 강의(A-1-2)에서 셸 안쪽을 본격적으로 뜯어본다. 지금은 "창 vs 프로그램 vs 방식"이 다르다는 것만 잡으면 된다.

### Terminal.app 처음 열어 보기 — 첫 화면 해부

macOS 기준으로 가장 빠르게 터미널을 띄우는 방법은 Spotlight(`⌘ + Space`)에 "터미널" 또는 "Terminal"을 치고 엔터.

처음 열리면 이런 화면을 만난다.

```
Last login: Sun Jun 22 09:14:21 on ttys000
kty@kty-MacBookPro ~ %
```

이 한 줄에 정보가 4개 들어있다.

```
kty @ kty-MacBookPro  ~  %
 │       │           │   │
 │       │           │   └─ 프롬프트 기호 (zsh는 %, bash는 $)
 │       │           └───── 현재 위치한 디렉터리 (~ 는 홈 디렉터리)
 │       └───────────────── 컴퓨터 이름 (호스트)
 └───────────────────────── 사용자 이름
```

[설명] 즉 위 한 줄은 "kty라는 사용자가 kty-MacBookPro라는 컴퓨터의 홈 디렉터리(`~`)에서, 명령을 받을 준비가 되었다(`%`)"는 뜻이다.

이 4개 요소(사용자·호스트·경로·프롬프트)는 PokéClip EC2에 SSH로 접속했을 때도 똑같이 나타난다. 단지 모양이 살짝 다를 뿐.

```
ec2-user@ip-172-31-12-45 ~ $
```

[설명] EC2 Amazon Linux는 `ec2-user`가 기본 사용자, 호스트가 IP 기반(`ip-172-31-12-45`), 셸이 bash라서 프롬프트가 `$`. 똑같은 4요소 구조다.

자, 명령을 하나 쳐 보자.

```bash
# 현재 시간 확인
date
```

엔터를 치면 이런 출력이 나온다.

```
Sun Jun 22 09:15:03 KST 2026
```

[설명] 이게 OS와의 첫 대화다. "지금 몇 시야?"라고 물었고 OS가 답한 것.

또 하나.

```bash
# 내가 누구인지 확인
whoami
```

```
kty
```

명령 1개에 한 줄짜리 응답 1개. 이게 CLI의 기본 리듬이다.

### 한 줄로 10단계를 대체하는 시연 — `mkdir -p a/b/c`

CLI의 진짜 매력은 "GUI로 N단계를 거쳐야 하는 작업이 한 줄로 끝난다"는 점에서 드러난다. 가장 단순한 예시 하나로 직접 시연한다.

**시나리오**: PokéClip 디렉터리 구조를 만들고 싶다.

```
pokeclip/
└── src/
    └── analysis/
        └── video/
```

**GUI로 만들기** (Finder 기준 — 직접 세 보면 정말로 10단계가 나온다):

1. Finder 실행
2. 홈 디렉터리로 이동
3. 우클릭 → "새로운 폴더"
4. 이름 입력: `pokeclip`
5. 만들어진 폴더 더블클릭
6. 우클릭 → "새로운 폴더"
7. 이름 입력: `src`
8. 들어가서 우클릭 → "새로운 폴더"
9. 이름 입력: `analysis`
10. 들어가서 우클릭 → "새로운 폴더" → `video`

마우스 클릭 10회 + 키 입력 4회. 약 15초.

**CLI로 만들기**:

```bash
# 한 줄로 3단 디렉터리 만들기
mkdir -p pokeclip/src/analysis/video
```

[설명] `mkdir`은 make directory의 약자. `-p`는 parents — 중간에 없는 상위 디렉터리도 함께 만들라는 옵션. 끝.

키 입력 약 40자, 약 4초.

체감하는 게 중요해서 한 번 더 직접 쳐 보자. 잘 만들어졌는지 확인은 다음 강의(A-1-2 진입) 미리보기 명령으로:

```bash
# 디렉터리 트리 확인 (find 사용 — 추후 A-2에서 본격)
find pokeclip -type d
```

```
pokeclip
pokeclip/src
pokeclip/src/analysis
pokeclip/src/analysis/video
```

이게 끝이다. 4개 디렉터리, 한 명령.

이 차이가 1회성일 때는 별것 아닌 듯 보인다. 하지만 같은 작업을 **방송 시작할 때마다 EC2 위에서 자동으로**, 그것도 **스트리머 100명 각자의 디렉터리 구조로** 만들어야 한다고 상상해 보라. GUI라면 사람이 1000번 클릭한다. CLI라면 셸 스크립트 한 줄에 `for` 반복문 하나 더해서 끝난다(A-3 트랙에서 본격).

### 서버는 GUI가 없다 — SSH 환경 미리보기

이 문장이 이 강의의 핵심 한 줄이다. **서버는 GUI가 없다.**

PokéClip의 AWS EC2 SRT 수신 서버를 예로 들면, 이 서버에 OBS에서 송출한 멀티 오디오 4트랙(마이크·게임·Discord·후원) MPEG-TS 스트림이 들어온다. 디버깅하려면 다음과 같은 작업을 한다.

- 들어오는 스트림 상태 확인
- FFmpeg 프로세스가 살아있는지 점검
- 디스크 용량 남았는지 확인 (1080p 보관 정책이라 용량 빨리 참)
- 분석 큐가 막혔는지 로그 추적

이 모든 작업을 **GUI 없이** 한다. 이유는 단순하다.

| 이유 | 설명 |
|---|---|
| 비용 | GUI를 띄우려면 X11/RDP 같은 무거운 데스크톱 환경 필요. EC2 비용 약 1.3~1.5배 증가 |
| 대역폭 | GUI는 화면 영상 자체를 네트워크로 전송. 텍스트 전송 대비 100배 이상 무거움 |
| 자동화 | GUI는 클릭 시뮬레이션이 불안정. CLI는 셸 스크립트로 100% 재현 |
| 보안 | GUI는 공격 표면(attack surface) 넓음. CLI 서버는 SSH 포트 1개만 열면 됨 |
| 관습 | Linux 서버 운영의 30년 표준 — 거의 모든 도구가 CLI 우선 |

SSH로 EC2에 접속하면 이런 화면이 나온다(미리 보기, 실제 접속은 추후 트랙에서).

```bash
# 로컬 터미널에서 EC2 접속
ssh -i ~/.ssh/pokeclip-key.pem ec2-user@52.78.123.45
```

[설명] `-i`는 identity 파일 옵션. `pokeclip-key.pem`이라는 비밀키로 본인을 증명. `ec2-user@IP`는 "그 IP의 ec2-user 계정으로 접속"이라는 뜻.

접속 성공 시:

```
Last login: Sun Jun 22 09:20:15 2026 from 121.130.45.12

       __|  __|_  )
       _|  (     /   Amazon Linux 2023
      ___|\___|___|

[ec2-user@ip-172-31-12-45 ~]$
```

[설명] 환영 메시지 후 프롬프트 한 줄. 마우스로 만질 게 하나도 없다. 처음부터 끝까지 CLI. 이게 백엔드 일의 일상 풍경이다.

### 학습자 흔한 두려움 5종과 해소

마지막 섹션. 입문자가 터미널 앞에서 망설이는 이유 5개를 하나씩 깬다.

| # | 두려움 | 실제 |
|---|---|---|
| 1 | "잘못 치면 컴퓨터가 망가질 것 같다" | 일반 사용자 권한으로는 시스템 파일을 못 건드린다. `sudo` 없이는 OS가 보호. 가장 위험한 명령(`rm -rf /`)도 sudo 없으면 막힘 |
| 2 | "명령어를 다 외워야 할 것 같다" | 절대 아니다. 매일 쓰는 명령은 약 20~30개. 나머지는 `--help`, `man`, `tldr`로 그때그때 찾는다 (A-1-3 본격) |
| 3 | "GUI 없이 어떻게 일하지" | 익숙해지면 GUI보다 2~5배 빠르다. 자동완성·히스토리 검색 두 기능만으로 타이핑 절반 줄어듦 (A-1-5 본격) |
| 4 | "검은 화면이 무섭다" | 색상·폰트·테마 자유롭게 바꿀 수 있다. iTerm2 + Oh My Zsh로 본인 취향에 맞게 꾸미면 오히려 GUI보다 더 정감 있어짐 (A-1-6 본격) |
| 5 | "오타 한 번에 사고가 날 것 같다" | 거의 모든 위험 명령은 확인 단계가 있다. `rm`도 `-i` 옵션이면 매번 묻는다. `rm -rf` 같은 무서운 명령은 알면 알수록 신중하게 쓰게 됨 |

5개 모두 공통점: **써 보지 않은 사람의 추상적 공포**. 한 주만 매일 켜면 다 사라진다.

추가 안전 팁 1개 — 처음 일주일은 **중요한 작업 디렉터리 안에서만** 명령을 친다. 홈(`~`)이나 시스템 디렉터리(`/etc`, `/usr`) 안에서는 신중하게. 이 한 가지만 지키면 사고 확률 거의 0이다.

### PokéClip 연결 — 이 강의가 어디에 쓰이는가

PokéClip 시스템 9단계 파이프라인 전체가 CLI 위에서 돌아간다.

| 파이프라인 단계 | CLI 사용 예시 |
|---|---|
| SRT Listener (EC2) | `ssh`로 접속, `systemctl status srt-listener`로 데몬 확인 |
| FFmpeg 디멀티플렉싱 | `ffmpeg -i srt://... -map 0:a:0 mic.aac` 같은 명령으로 트랙 분리 |
| YOLO 영상 분석 | `python analyze.py --input video.mp4 --model yolov8s.pt` 식 실행 |
| Whisper STT | API 호출도 CLI에서 `curl` 또는 Python 스크립트로 |
| Lambda 배포 | `aws lambda update-function-code` 한 줄 |
| 로그 확인 | `tail -f /var/log/pokeclip.log`로 실시간 추적 |

이 시리즈(A-1)를 마치고 A-2(Linux 명령어 일상)와 A-3(Bash 스크립팅)을 끝내야 위 작업들을 **이해하고 따라 칠 수 있다**. 그 전까지는 "왜 이 명령이 거기서 나오는지"가 안 보인다.

### 다음 강의 미리보기

다음 강의(A-1-2)에서는 "셸이라는 프로그램"의 정체를 본격적으로 뜯어본다. bash와 zsh의 차이, 왜 macOS가 zsh로 갈아탔는지, EC2 서버는 왜 여전히 bash인지. 그리고 프롬프트 `%`와 `$`의 의미.

이 강의에서 익혀 둘 것 딱 두 개:

1. 터미널 열어서 `date`, `whoami`, `mkdir -p a/b/c` 직접 쳐 보기
2. 어디서든 무서움 없이 검은 창을 띄울 수 있다는 자신감

### 실무 적용 시나리오

PokéClip 운영에서 CLI가 등장하는 실제 순간 3가지.

**시나리오 1 — 스트리머 100명 환경 일괄 생성**
```bash
# 새 베타 스트리머 100명에게 각자 작업 디렉터리 생성
for i in $(seq 1 100); do
  mkdir -p ~/streamers/user_$i/{recordings,clips,logs}
done
```
GUI라면 사람이 1000번 클릭해야 할 일이 셸 스크립트 한 줄로 끝남.

**시나리오 2 — EC2 분석 서버 디버깅 (밤 2시 장애)**
```bash
# SSH로 들어가서 무엇이 꺼져있는지 즉시 확인
ssh ubuntu@ec2-13-209-xx-xx.compute.amazonaws.com
ps aux | grep -E "ffmpeg|whisper|yolo"
tail -50 /var/log/pokeclip/analysis.log
df -h  # 디스크 가득 찼는지
```
GUI 데스크톱 환경 없어도 SSH + 텍스트만으로 5초 안에 진단 시작.

**시나리오 3 — 인시던트 리포트 작성**
```bash
# 장애 재현용 명령을 그대로 팀에 공유
docker exec -it pokeclip-analyzer python -m analysis.replay \
  --stream-id S_2026_0623_001 \
  --start-ts 2026-06-23T01:14:23Z
```
"메뉴 어디 누르고 다음 누르고" 식 GUI 절차는 글로 옮기기 어려운데, CLI는 명령어 한 줄 복사 = 누구든 정확히 같은 결과 재현.

이 셋이 백엔드 일의 70~90% — 자동화 / 원격 / 재현성. GUI가 나쁜 게 아니라 도구가 다른 것.

### 1강 핵심 3줄

1. 터미널은 OS와 텍스트로 대화하는 창, 셸은 그 안에서 명령을 해석하는 프로그램 — 4개 용어(터미널·콘솔·셸·CLI)가 가리키는 게 각각 다르다.
2. CLI를 쓰는 진짜 이유는 **자동화·원격·재현성** 3축이며, GUI 10단계 작업이 `mkdir -p a/b/c` 한 줄로 4초에 끝난다.
3. AWS EC2 같은 서버에는 GUI가 없다 — PokéClip의 SRT 수신·FFmpeg 디멀티플렉싱·YOLO 분석 9단계 파이프라인 전체가 CLI 위에서 돌아간다.
