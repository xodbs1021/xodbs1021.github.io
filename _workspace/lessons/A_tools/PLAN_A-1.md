# 시리즈 계획 A-1 — 터미널 + zsh 입문

## 시리즈 한 줄 hook
모든 백엔드/AI/AWS 작업의 시작점인 터미널을, GUI 사용자가 두려움 없이 매일 쓰는 도구로 만든다. PokéClip의 EC2 접속·Docker 실행·Python 개발이 전부 여기서 출발.

## PokéClip 적용 영역
모든 코드 실행/AWS 디버깅/Docker 컨테이너 조작/Python 가상환경/Git 작업의 기반 인터페이스. 이 시리즈 없이는 이후 모든 트랙(B Python ~ Q DSA) 진행 불가.

## 선행 시리즈
없음 (커리큘럼 전체의 진입점)

## 시리즈 범위 (마스터 인용)
- 다룰 핵심 항목: 터미널 vs GUI / 셸 (bash/zsh) / 프롬프트 / 명령어-인자-옵션 / 환경 변수 / PATH / 탭 자동완성 / 히스토리 / Oh My Zsh / iTerm2
- 다루지 않는 것:
  - 파일 시스템 명령 (ls/cd/cat 등) → A-2
  - 셸 스크립팅 (변수/조건문/반복문) → A-3
  - 프로세스 관리 깊이 (ps/top/시그널) → N 트랙

## 강의 수 결정 근거 (패턴화 자기 점검)

마스터 핵심 항목 10개를 콘텐츠 결합도에 따라 **6묶음**으로 분할:
1. (개념/두려움 해소) — 터미널 vs GUI + 용어 구분
2. (셸 정체) — bash/zsh + 프롬프트 읽기
3. (명령 문법) — 명령어·인자·옵션 + 도움말
4. (환경/PATH) — 환경 변수 + PATH ("command not found" 디버깅 단독 강의 필요)
5. (생산성) — 탭 자동완성 + 히스토리
6. (커스텀) — iTerm2 + Oh My Zsh

**왜 5강이 아닌가**: 5강 병합 시 가장 자연스러운 후보가 (4+5) 또는 (5+6). (4+5)는 380+300=680줄로 한 강의 너무 무겁고, (5+6)은 300+360=660줄 + 생산성과 커스텀이 톤이 달라 부자연. **분량 불균형으로 기각**.

**왜 7강이 아닌가**: 과분할 시 1강당 항목 1.5개 미만. "환경 변수와 PATH"는 한 사고 흐름이라 분리 시 흐름 깨짐. **콘텐츠 본질 기각**.

**영상 트랙(3/4/4/4/4) 패턴 자기 점검**: 4-X 갯수와 무관. 마스터 10항목을 묶음으로 보면 자연스럽게 6묶음으로 떨어짐. 직전 시리즈 갯수가 머릿속에 떠올라 영향 주지 않았음.

## 강의 구성

### A-1-1: 터미널이 뭐고 왜 써야 하는가 — GUI를 버려야 하는 순간들
- 핵심 다룰 항목:
  - 터미널 vs GUI: 표현력·자동화·원격 접근 차이
  - "터미널/콘솔/셸/CLI" 용어 구분 (혼동 정리)
  - macOS 기본 Terminal.app 실행과 첫 화면 해부
  - 한 줄 명령으로 GUI 10단계를 대체하는 시연 (`mkdir -p a/b/c`)
  - 서버는 GUI가 없다 — SSH 환경 미리보기
  - 학습자 흔한 두려움 5종과 해소
- 예상 분량: ~280줄
- 트레이드오프 포인트: GUI는 발견성(discoverability)이 높고 CLI는 효율성·재현성이 높다 — 둘 다 도구일 뿐 우열 아님
- 면접 답변 주제: "왜 CLI를 쓰시나요" — 자동화·원격·재현성 3축으로 답하는 프레임
- 선행 강의: 없음
- PokéClip 적용 인용: PokéClip EC2 SRT 서버는 GUI가 없다. 모든 디버깅이 CLI 위에서 일어난다

### A-1-2: 셸이라는 프로그램 — bash와 zsh, 그리고 프롬프트의 정체
- 핵심 다룰 항목:
  - "터미널은 창, 셸은 그 안에서 도는 프로그램" 분리 이해
  - bash와 zsh의 역사 (Bourne → Bash → Zsh)와 macOS 기본이 zsh가 된 이유
  - 현재 셸 확인 (`echo $SHELL`, `ps -p $$`)
  - 프롬프트(`$`, `%`, `#`) 읽는 법 — 사용자/호스트/경로/권한 표식
  - 프롬프트 커스터마이즈 가능성 미리보기 (A-1-6에서 본격)
  - 셸 전환 (`chsh -s`)과 로그인 셸 vs 인터랙티브 셸 개념 맛보기
- 예상 분량: ~300줄
- 트레이드오프 포인트: bash 호환성(서버 기본) vs zsh 편의성(로컬 개발) — macOS는 zsh, EC2 Amazon Linux는 bash. 둘 다 익숙해야 함
- 면접 답변 주제: "bash와 zsh 차이 / 왜 회사 서버는 보통 bash인가"
- 선행 강의: A-1-1
- PokéClip 적용 인용: 로컬 개발(zsh) ↔ EC2 운영(bash) 양쪽을 매일 오감. 차이를 모르면 스크립트가 한쪽에서만 동작

### A-1-3: 명령어의 문법 — 명령어·인자·옵션 그리고 도움말 읽기
- 핵심 다룰 항목:
  - 명령어 = `프로그램명 [옵션] [인자]` 구조 분해
  - 짧은 옵션(`-l`) vs 긴 옵션(`--long`) vs 옵션 결합(`-la`)
  - 옵션과 인자의 순서·구분(`--`)
  - 도움말 3종: `--help`, `man`, `tldr` — 언제 무엇을 쓰는지
  - man 페이지 SECTIONS(NAME/SYNOPSIS/OPTIONS) 읽는 법
  - 종료 코드(`$?`) 처음 만나기 — 0은 성공, 0이 아니면 실패
- 예상 분량: ~320줄
- 트레이드오프 포인트: 옵션이 많은 명령(`find`, `tar`)은 외우지 말고 man을 읽는 습관 — 외우기 vs 찾기
- 면접 답변 주제: "처음 보는 명령을 어떻게 익히시나요" — man·tldr·--help 워크플로
- 선행 강의: A-1-2
- PokéClip 적용 인용: `ffmpeg`·`aws`·`docker` 모두 옵션이 수십 개. 문법 구조를 모르면 공식 문서를 못 읽음

### A-1-4: 환경 변수와 PATH — "command not found"의 진짜 원인
- 핵심 다룰 항목:
  - 환경 변수란 무엇인가 (프로세스가 들고 다니는 key=value 보따리)
  - `export`, `env`, `printenv`로 보기/설정/제거
  - PATH 변수의 정체: 콜론으로 구분된 디렉터리 목록을 순서대로 탐색
  - `which`, `type`, `command -v`로 어디서 실행되는지 추적
  - `~/.zshrc`, `~/.zprofile`, `/etc/paths` — 어디에 PATH를 써야 하는가
  - "command not found" 디버깅 5단계 체크리스트
  - HOME / USER / LANG / EDITOR 같은 흔한 환경 변수
- 예상 분량: ~380줄
- 트레이드오프 포인트: PATH 앞에 추가 vs 뒤에 추가 — 우선순위 결정. pyenv/nvm 같은 버전 관리자가 PATH 앞을 차지해야 하는 이유
- 면접 답변 주제: "PATH란 무엇이며 어떻게 설정하시나요" / "shim이 뭔지"
- 선행 강의: A-1-3
- PokéClip 적용 인용: pyenv로 Python 3.11 설치 / Homebrew로 ffmpeg 설치 / AWS CLI 인식 — 전부 PATH가 핵심. PokéClip B-4 가상환경의 선결 지식

### A-1-5: 손가락이 두 배 빨라지는 두 가지 — 탭 자동완성과 히스토리
- 핵심 다룰 항목:
  - 탭 자동완성의 원리 (셸이 PATH·파일 시스템·옵션 사전 참조)
  - zsh의 탭 메뉴(하이라이트 선택) 활용
  - 히스토리 기본 (`history`, `!!`, `!$`, `!ffmpeg`)
  - Ctrl+R 역방향 검색 — 가장 자주 쓰게 될 단축키
  - 히스토리 파일(`~/.zsh_history`)과 크기/중복 제거 설정
  - 위험: `rm`을 히스토리에서 재실행할 때 주의
  - 자주 쓰는 셸 단축키(Ctrl+A/E/U/K/W) 6종
- 예상 분량: ~300줄
- 트레이드오프 포인트: 별칭(alias) vs 히스토리 검색 — 1회성은 Ctrl+R, 반복되면 alias. 둘 다 안 쓰면 매번 풀 타이핑
- 면접 답변 주제: "터미널에서 생산성 어떻게 끌어올리시나요"
- 선행 강의: A-1-4
- PokéClip 적용 인용: 긴 `ffmpeg -i ... -c:v libx264 ...` 명령을 매번 칠 수 없음. 히스토리·자동완성이 일상 도구

### A-1-6: 도구를 내 손에 맞추기 — iTerm2와 Oh My Zsh 세팅
- 핵심 다룰 항목:
  - 기본 Terminal.app vs iTerm2 — 분할 창·검색·프로파일·핫키
  - iTerm2 설치와 첫 5분 설정 (테마·폰트·키매핑)
  - Oh My Zsh 설치 (`curl` 한 줄)와 내부 구조 (`~/.oh-my-zsh`)
  - 테마 변경 (robbyrussell → agnoster/powerlevel10k 맛보기)
  - 필수 플러그인 3종 — git / zsh-autosuggestions / zsh-syntax-highlighting
  - `.zshrc` 변경 후 `source` 또는 새 셸 — 적용 메커니즘
  - 과한 커스터마이즈의 함정: 다른 환경(서버) 갔을 때 무력해짐
- 예상 분량: ~360줄
- 트레이드오프 포인트: 화려한 프롬프트(powerlevel10k) vs 가벼움(robbyrussell) — 정보 밀도와 시작 속도의 균형. 서버는 결국 기본 bash
- 면접 답변 주제: "본인 개발 환경 한 번 설명해 주세요"
- 선행 강의: A-1-5
- PokéClip 적용 인용: iTerm2 분할 창에서 한쪽은 EC2 SSH·한쪽은 로컬 빌드·한쪽은 로그 tail — PokéClip 개발 일상의 기본 레이아웃

## 시리즈 결과
이 시리즈를 마치면 학습자는:
- 터미널을 두려움 없이 매일 켤 수 있다
- bash와 zsh의 차이를 한 문장으로 설명할 수 있다
- 명령어 한 줄을 보면 옵션·인자를 분해해서 man을 읽을 수 있다
- "command not found"가 떴을 때 PATH부터 점검할 수 있다
- Ctrl+R로 히스토리를 검색하고 탭으로 절반 이상 타이핑을 줄인다
- iTerm2 + Oh My Zsh로 자기 환경을 세팅하고 `.zshrc`를 직접 편집한다
