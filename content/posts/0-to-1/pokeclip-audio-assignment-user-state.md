음악 없는 클립을 만들려면 게임·마이크·음악 같은 소리가 독립 트랙에 남아야 한다. 그렇다고 방송자에게 OBS 체크박스를 전부 다시 맞추게 하면 본방이나 녹화용 소리가 달라질 수 있다. 자동 배정은 설정을 편하게 만드는 기능인 동시에, 사용자의 기존 작업 환경을 바꾸는 기능이었다.

나는 미디어 서버가 기대하는 트랙 구성과 사용 흐름을 정하고 OBS 담당 팀원과 기존 설정 보호·복원·순간 표시의 계약을 검토했다. [PR #195](https://github.com/3K-PokeClip/PokeClip-mono/pull/195)의 구현과 OBS 실측은 jaehwan-space가 맡았다. 이 글은 그 팀 결과를 바탕으로 내가 선택·조율한 입력과 통합 경계를 설명한다.

## “첫 오디오”와 “믹서 0”은 같지 않았다

서버 입력의 첫 오디오에는 본방 믹스가 있어야 한다. 그런데 방송자가 OBS의 본방 트랙을 2번으로 선택했다면, 믹서 0을 고정해서 만드는 첫 오디오는 본방과 다를 수 있다. 숫자상 첫 칸과 제품에서 말하는 본방의 의미가 어긋나는 경우다.

팀 구현은 본방 AAC 인코더를 믹서 번호와 무관하게 공유하고, AAC가 아니라면 같은 본방 믹서에 대응하는 대체 인코더를 만드는 방식으로 보완했다. 서버는 고정된 입력 순서를 기대하지만 그 입력을 만드는 플러그인은 실제 사용자 설정을 읽어야 했다. [OBS의 다중 트랙 가이드](https://obsproject.com/kb/multiple-audio-track-recording-guide)가 설명하는 믹스와 개별 트랙의 구분을 제품 계약에 적용한 셈이다.

## 자동화의 기본값은 꺼짐과 복원이었다

오디오를 내는 소스 후보에 스템을 배정하고 이전 배정 기억을 우선 사용하도록 했다. 소리가 없는 오버레이가 먼저 자리를 차지하거나 방송할 때마다 같은 소스가 다른 트랙으로 이동하는 일을 줄이려는 정책이다. 동시에 본방·VOD 트랙을 보호하고, 방송·녹화·리플레이 버퍼 사용 중에는 새 배정을 즉시 덮어쓰지 않게 했다.

| 경계 | 선택한 동작 | 이유 |
|---|---|---|
| 첫 사용 | 자동 배정 기본 꺼짐, 사용자가 동의 후 활성화 | 기존 녹화 구성을 바꿀 수 있음 |
| 다시 사용 | 이전 배정을 우선 활용 | 소스와 스템 대응의 불필요한 이동 방지 |
| 장면 컬렉션 전환 | 컬렉션별 백업 | 서로 다른 원래 체크를 구분해야 함 |
| 자동 배정 해제 | 해당 컬렉션의 원래 체크 복원 | 편의 기능을 끈 뒤 이전 작업 환경으로 돌아감 |

백업이 있다는 사실만으로 복원이 보장되지는 않는다. A 컬렉션에서 저장한 설정을 B 컬렉션에 복원하면 또 다른 변경이 된다. 팀 검증에서는 A/B를 바꾼 뒤 각각 자동 배정을 껐을 때 원래 체크로 돌아가는지 확인했다. 백업 범위·잠금·보호 트랙을 깨뜨리는 결함 주입 테스트도 남겼다.

## 트랙 수 다음에는 실제 소리를 확인했다

검증 환경은 OBS 32.2.2 macOS → SRT → 로컬 MediaMTX 녹화였다. 440Hz와 1,000Hz 소스를 켠 뒤 방송 중 2,500Hz 소스를 추가했다. 파일과 HLS 목록을 확인하는 검사에 트랙별 대역 음량을 더했다.

| 검사 | 관측 |
|---|---|
| ffprobe | 영상 1개 + AAC 6개 |
| HLS 목록 | 대체 오디오 6개 |
| 스템의 목표 대역 | −24.1dB |
| 빈 트랙 | −91.0dB |
| 본방 트랙 2 | 첫 오디오에 본방의 440Hz 보존 |
| 컬렉션 A/B | 각각의 원래 체크 복원 |

다른 대역에서 읽힌 −47~−57dB는 측정 필터의 누설이므로 원음 혼입률로 단정하지 않았다. 실제 음악을 제거한 청감 품질 검증도 아니다. 빈 트랙 역시 패킷 없이 멈춰 있는 것이 아니라 무음 패킷을 계속 보내야 모든 트랙을 기다리는 출력 경로가 진행할 수 있었다.

## 순간 표시 버튼도 서버 계약이 필요했다

같은 PR에는 하이라이트 순간 표시가 연결된다. 사용자가 버튼을 한 번 눌렀는데 전송 결과를 받지 못하면, 새 식별자를 만들어 재시도할 경우 같은 순간이 여러 개 생길 수 있다. 그래서 같은 `eventId`로 재시도하고 만료와 영구 오류를 구분하는 계약을 뒀다.

이것은 UI에 버튼이 생겼으니 서버에도 표시가 저장된다는 뜻이 아니다. Clip의 저장 창구와 방송 생명주기 이벤트가 선행돼야 한다. 플러그인 구현과 서버의 준비 상태를 나눠야 화면의 완성도를 전체 기능의 완성으로 오해하지 않는다.

## 편의를 추가할 때 되돌아갈 길도 함께 만든다

자동 배정은 수동 설정을 모두 없애는 기능이 아니다. 녹화 전용 트랙도 같은 OBS 체크를 쓰므로 기존 녹화 방식에 따라 끄는 선택이 필요하다. 또한 로컬 macOS 검증을 Windows와 실제 치지직 송출까지 확장해 말할 수 없다.

이 사례에서 남은 판단은 자동화가 사용자의 상태를 소유해 버리지 않게 하는 것이다. 켜는 경로만큼 끄는 경로를 검토하고, 숫자로 된 트랙 위치만큼 본방이라는 의미를 확인해야 했다. 편집 가능한 입력을 만드는 일은 소리를 나누는 기능과 기존 방송을 보호하는 책임을 함께 설계하는 일이었다.
