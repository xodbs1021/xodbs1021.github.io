채팅이 많이 올라오는 순간을 클립으로 만들면 하이라이트가 될 것 같았습니다. 그러나 평소부터 채팅이 많은 채널과 한 사람이 메시지를 반복하는 상황을 같은 방식으로 세면, “많이 입력됐다”와 “많은 사람이 장면에 반응했다”가 섞입니다. 자동 카드를 계속 만들 수 있다는 사실이 유용한 장면을 찾았다는 증거는 아닙니다.

이 글은 **성능이 검증된 탐지 모델의 도입기보다, 무엇을 실험해야 하는지 정리한 연구·제품 설계 기록**입니다. PokeClip 팀의 하이라이트 연구를 바탕으로 저는 미디어 시간과 탐지 결과를 연결할 요구, 자동 탐지가 실패할 때의 제품 경로를 정리했습니다. 채널별 임계값·시간 창·고유 채터 비교 실험은 아직 미결이며, 정확도 개선률이나 사용자 성과를 제시할 근거는 없습니다.

## 메시지 수 하나로는 다른 원인이 섞인다

영상의 사건에 반응하는 채팅과 시청자끼리 대화하는 채팅은 메시지 수라는 관측에서는 비슷하게 보일 수 있습니다. 한 사람이 여러 번 입력하면 메시지 수는 늘어도 반응한 사람의 수는 그대로입니다. 따라서 메시지 수 외에 서로 다른 참여자 수의 급증도 신호 후보로 두었습니다.

채널 간 비교에도 같은 문제가 있습니다. 평소 채팅량이 다른 채널을 하나의 절대값으로 자르면 큰 채널의 일상적인 대화가 작은 채널의 강한 반응보다 높게 나올 수 있습니다. 그래서 채널 내부의 평소 흐름과 비교하는 기준선이 필요하다고 보았습니다. 다만 고유 참여자 수나 증가율을 추가했다고 오탐이 줄었다고 말할 수는 없습니다. 이들은 비교할 실험 후보이지 검증된 개선책이 아닙니다.

| 신호 후보 | 구분하려는 상황 | 추가로 확인할 것 |
|---|---|---|
| 채팅 수의 변화 | 평소보다 반응이 급증했는가 | 채널별 기준선과 임계값 |
| 고유 참여자 수 | 소수의 반복 입력인가, 참여가 넓어졌는가 | 실제 반응 장면과의 대조 |
| 여러 시간 창의 합의 | 짧은 급등과 지속적인 반응을 구분할 수 있는가 | 창 길이에 따른 오탐·누락 |
| 수동 순간 표시 | 자동 신호가 약해도 사람이 장면을 남길 수 있는가 | 방송·편집 흐름과의 연결 |

## 실시간에는 미래의 평균을 사용할 수 없다

방송이 끝난 뒤 전체 채팅을 분석할 때와 라이브 중 카드를 발행할 때는 쓸 수 있는 정보가 다릅니다. 사후 전체 평균을 기준으로 삼는 방식이 좋아 보여도, 라이브 시점에는 아직 오지 않은 데이터가 포함돼 있습니다. 실시간에 가능한 누적·롤링 기준선을 구분해 검토한 이유입니다.

방송 초반에는 비교할 이력이 부족합니다. 이때 무조건 점수를 만들기보다 준비 구간 동안 카드 발행을 보류하는 방향을 남겼습니다. 또 방송 도중 시청자 규모가 변하면 오래된 기준선이 현재 상태를 설명하지 못할 수 있어, 최근 구간을 기준으로 변화를 따라가는 방향을 연구 후보로 두었습니다.

이 단계에서 구체적인 준비 시간이나 창 길이를 확정된 값처럼 쓰지 않았습니다. 그 숫자는 채널별 데이터와 반례를 대조한 뒤 정해야 합니다. “실시간이어야 한다”는 요구를 만족시키는 설계 조건과, 실제로 좋은 구간을 골라내는 모델 파라미터는 분리해야 했습니다.

## 채팅 시각을 영상 시각으로 그대로 쓰지 않는다

채팅이 서버에 도착한 순간이 영상 사건의 발생 순간과 같지는 않습니다. 시청자는 플랫폼의 재생 지연을 거친 화면을 보고 반응합니다. 따라서 채팅 시각을 곧바로 미디어 위치로 넘기면 카드가 장면보다 뒤를 가리킬 수 있습니다.

수집의 시작·종료는 방송 생명주기와 연결하고, 탐지 결과를 편집에 넘길 때는 미디어 타임라인과 대조하도록 요구를 정리했습니다. 수집기, 탐지 모델, 편집에 넘기는 카드의 책임도 나눴습니다. 이후 신호 모델이 바뀌더라도 편집 기능까지 같은 모델의 내부 표현에 묶이지 않게 하려는 설계입니다. 지연 보정의 최적값이나 플랫폼별 정확도가 이미 검증됐다는 뜻은 아닙니다.

## 자동 탐지가 실패해도 편집은 가능해야 했다

채팅이 적거나 자동 후보를 믿기 어려운 채널에 억지로 카드를 제공하면, 사용자가 잘못된 제안을 확인하는 부담을 떠안습니다. 그래서 충분한 신뢰를 얻지 못한 경우 핫키·수동 표시 경로를 안내하도록 제품 대안을 정리했습니다. 수동으로 남긴 구간도 같은 편집·BGM 제거·자막 경로를 사용할 수 있게 하는 방향입니다.

| 현재 남긴 것 | 대표 성과로 주장하지 않는 것 |
|---|---|
| 팀 연구를 바탕으로 한 신호 후보·예외 정리 | 제가 독자 개발한 탐지 알고리즘 |
| 방송 생명주기와 미디어 시간의 연결 요구 | 모든 플랫폼에서 입증한 시간 보정 정확도 |
| 자동 후보의 신뢰가 낮을 때 수동 경로 | 사용자 생산성이나 모델 정확도 개선률 |

이 때문에 이 사례는 [포트폴리오 54쪽의 참고 기록](/portfolio/2026-10-15-v2/full.pdf#page=54)으로 남겼습니다. 대표 사례로 강화하려면 팀 연구 중 제가 선택한 대안을 더 구체적으로 추적하고, 실제 반례를 대상으로 결과를 비교해야 합니다. 기록을 공개하는 것과 검증이 완료됐다고 주장하는 것은 다릅니다.

자동 탐지의 성공 여부만으로 제품 전체의 가치가 결정되지 않도록 한 점은 이 연구에서 남길 판단입니다. 채팅 신호가 충분하지 않아도 사용자가 장면을 표시하고 편집할 수 있어야 합니다. 앞으로의 실험은 더 많은 신호를 넣는 데서 끝나지 않고, 자동 제안이 언제 도움이 되며 언제 수동 경로가 더 나은지까지 확인해야 합니다.
